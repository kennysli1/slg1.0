# 加新功能检查清单

> 每次加新宝物/科技/效果类型/modifier 时，按这个清单走。**
> 每步有 ✅ 动作 + ❌ 今天踩过的坑。

---

## 一、先写测试，再写代码

```bash
# 1. 在 modifier-coverage.test.ts 加一个判断
# 2. 先让它 FAIL（证明新字段确实被漏了）
# 3. 再写代码让它 PASS
```

| ✅ 做这个 | ❌ 不做会怎样 |
|----------|-------------|
| 测试里注入新 modifier → 调目标 API → 断言返回值含新字段 | 服务端加了但 API 没返，客户端永远看不到 |

**测试模板**（往 `modifier-coverage.test.ts` 里加）：
```ts
it('新宝物X → GetArmy 返回字段 Y', async () => {
    // 注入 modifier
    await commands.send({ name: 'xxx.SetXxx', payload: { villageId: vid, ... } });
    // 查询 API
    const res = await commands.send({ name: 'yyy.GetYyy', payload: { villageId: vid } });
    // 断言
    assert.ok((res.payload as any).newField != null, 'newField 缺失');
});
```

## 二、数据流三步走

**每加一个 state 字段，必须走完这三步：**

```
① State 加字段          → 落盘
② Set* 命令接收并存储    → 运行时写入
③ 所有 Get* API 包含它   → 客户端读取
```

| 步骤 | 检查方法 |
|------|---------|
| ① | `grep -n "字段名" packages/server/src/modules/目标模块.ts` |
| ② | 搜索 `commands.register` 确认已注册 + 有 handler |
| ③ | **在同一个文件里搜索所有 `return { ok: true, payload:`** ——每个出口都必须包含新字段 |

> ❌ 教训：`popState.overflowRatio` 加了 ① 和 ②，但 `applyPopPayload`（客户端接收函数）里漏了 → 服务端有值，客户端永远 0。

**客户端侧额外检查**：
- `refresh.ts` 里所有 `apply*Payload` 函数必须同步加字段
- `state.ts` 里的 interface（`PopSnapshot` 等）必须同步加字段

## 三、调用已有命令前，读源码确认签名

```
❌ 想当然：ConsumePop({ amount: 50 })
✅ 看源码：ConsumePop({ unit: 'legionnaire', count: 5 })
```

| ✅ 做这个 | ❌ 今天踩的坑 |
|----------|-------------|
| `grep -A15 "private.*方法名" 目标模块.ts` | `ConsumePop` 参数名是 `count` 不是 `amount` → 静默失败 |
| 确认要不要传递 `unit` 等业务字段 | 没传 `unit` → `config.units[undefined]` = undefined → `unknown_unit` |
| 确认有没有副作用（如 `trainingPopCost` 增加） | ConsumePop 会产生训练预留 → 伯乐用完出现 66 训练人口 |

## 四、跨异步调用时加安全边距

```
两个异步查询之间数据可能漂移（settle/其它进程修改）
❌ ratio = exact  → TrySpend 差 1 单位
✅ ratio × 0.95 + 降级重试
```

| ✅ 做这个 | ❌ 今天踩的坑 |
|----------|-------------|
| ratio 留 5% 安全边距 | GetResources→TrySpend 差 1 木 → `insufficient:wood` |
| TrySpend 失败时不丢数据，做降级重试 | 宝物已消费但没生效，还丢了 |

## 五、枚举值用完整分派，不猜上下文

```
❌ if (isInstant) → "获得 X 金币"  // 所有 instant 都当金币
✅ if (effectType === 'instantGold') → "...金币"
   else if (effectType === 'cavalryTrainSpeed') → "...骑兵翻倍"
```

| ✅ 做这个 | ❌ 今天踩的坑 |
|----------|-------------|
| 按 `effectType` 分派，不全依赖 `applyType` | 伯乐使用后显示"获得 50 金币" |
| 新 effectType 加一个分支 | — |

## 六、部署后自检

```bash
# 不要只看 build + reload 成功就完了
ssh kow 'cd /home/ubuntu/kow && npm run build && pm2 reload kow && sleep 2 && pm2 status | grep -q online && echo OK || (echo "SERVER DOWN!"; pm2 logs kow --lines 5 --nostream)'
```

| ✅ 做这个 | ❌ 今天踩的坑 |
|----------|-------------|
| `pm2 status` 确认 `online` | 白名单没加 → 服务挂了 3 分钟才发现 |
| deploy 命令末尾固定加这一行 | — |

## 八、commit 前检查

- [ ] `npm run build` 全绿（服务端 + 客户端）
- [ ] 相关测试通过（`modifier-coverage.test.ts` 包含新字段）
- [ ] `git diff --stat` 确认没漏文件、没多文件
- [ ] CHANGELOG 或 commit message 写清楚改了哪些文件
