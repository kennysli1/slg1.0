# 筛色子实验场

## 范围与隔离

筛色子实验场是 `packages/dice-lab` 独立 workspace 包和独立 Fastify 进程 `kow-dice-lab`。主游戏不会导入它的规则、会话或前端状态；实验场也不读取 KOW `Store`、WAL、WebSocket 协议或玩家存档。主服务只提供一层可选的同域反向代理，因此实验场不可用时主游戏仍可正常运行。生产入口为 `/dice-lab/`，直接服务监听 `127.0.0.1:8091`。

当前按“刷新/掉线重新开始”处理：会话只在服务内存保留，默认 30 分钟未访问过期，最多 500 局；进程重启不会恢复对局。接入任务系统前必须另立 Command/Event 契约，不能把实验场状态直接写进主游戏模块。

## 玩法规则

- 普通六面骰，玩家先手，目标分数默认 4,000（测试界面可选 2,000/4,000/6,000）。
- 1 点计 100 分、5 点计 50 分；`1、2、3、4、5` 计 500 分，`2、3、4、5、6` 计 750 分，`1、2、3、4、5、6` 计 1,500 分。1 点和 5 点可以作为额外单骰与顺子或同点数组合叠加计分（例如 `1、2、3、4、5、1` 为 600 分）。
- 三个相同点数：1 为 1,000 分，2–6 为 200/300/400/500/600 分；四个、五个、六个相同点数分别为三同的 2/4/8 倍（例如六个 1 为 8,000 分）。每次必须选择完整的合法组合；本版本不再把三对作为计分组合。
- 保留计分骰后继续掷剩余骰；保留骰已经从桌面移出，不会和后续新骰重新组成三同或顺子，但分数会累加到同一个未收下的本轮分数中。六骰全部计分触发热骰并重新掷六骰。没有可计分组合则爆骰，丢失本轮尚未收下的分数并交给 NPC；客户端会在同一牌桌保留爆骰点数约 3.2 秒后再让 NPC 开始回合。
- 当前回合面板会列出前面阶段每次保留的骰子组合与分值，便于核对本轮累计分数。NPC 回合会按服务器返回的掷骰、选骰、热骰、收分或爆骰事件逐步播放，每个动作约停留 1.35 秒。
- NPC 回合沿用玩家牌桌的计分层：顶部分数按已播放事件逐步更新，回合标题下显示 NPC 当前阶段的保留组合与累计分数；普通 NPC 牌面使用蓝色，只有爆骰事件使用红色提示，未选中的骰子不显示“可用”标签，选中的骰子才显示“保留”。
- 玩家爆骰也按 NPC 的分阶段节奏展示：先在固定牌桌区域显示新摇出的骰子并短暂停留，随后才切换红色并显示爆骰提示；计分板始终保留在页面顶部，不因爆骰流程卸载而产生布局跳动。
- 玩家爆骰牌面阶段保留本轮前面阶段的计分明细与累计分数；牌面揭示阶段沿用普通桌面样式，不显示额外的“新牌面”提示，约 0.9 秒后才在同一桌面切换红色爆骰样式。
- NPC 牌面区域与玩家骰子区域使用相同的最小高度和上下间距，切换回合时保持布局稳定。
- 选择“收下本轮分数”才写入自己的总分；先达到目标者获胜。爆骰时失败牌面直接留在牌桌并显示爆骰提示，约 3.2 秒后才进入 NPC 回合。达标方在计分板显示醒目标记，并在牌桌上保留最终骰子、胜负和牌型，直到点击“再来一局”才清除。

规则实现集中在 `src/domain/rules.ts`，状态机在 `src/domain/engine.ts`；HTTP 层只做输入校验、会话并发 revision 检查和结果序列化。

## NPC

`easy`、`normal`、`hard` 三档共用同一规则与服务器随机源，仅决策阈值和风险偏好不同。NPC 会记录掷骰、保留、收分、爆骰和热骰事件，并把每个动作及当时牌面交给客户端播放；客户端不执行胜负或计分逻辑。

## 接口与运行

```text
GET  /health
POST /dice-lab/api/sessions
GET  /dice-lab/api/sessions/:id
POST /dice-lab/api/sessions/:id/actions
DELETE /dice-lab/api/sessions/:id
```

生产可通过 `DICE_LAB_ENABLED=off` 关闭服务，`DICE_LAB_PORT`、`DICE_LAB_HOST`、`DICE_LAB_TOKEN` 可由 PM2 环境覆盖。开启 token 时使用 `x-dice-lab-token`，不要把 token 写进 Git 或配置 CSV。

本地验证：

```bash
npm run build:dice-lab
npm run test:dice-lab
npm run test:deploy
```

`scripts/dice-lab-smoke.mjs` 会启动临时独立进程，检查静态页面、生成会话、旧 revision 拒绝和动作链；不会创建主游戏玩家或修改任何存档。

## 美术

骰子与计分板是通过项目 ImageGen/art pipeline 生成的装饰资源，放在 `packages/dice-lab/public/art/`。点数位置和交互状态仍由 CSS/DOM 绘制，避免把规则绑定到图片。生产构建把它们作为实验场静态资源发布，主游戏资源目录不复用。
