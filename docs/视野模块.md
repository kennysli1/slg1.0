# 视野模块

## 职责与状态

`modules/vision.ts` 是玩家战争迷雾的唯一 owner，独占 `vision` 集合。每位玩家的文档以玩家 id 为主键，`explored["q,r"]` 保存该格最后一次可见时的地图快照；首次使用时惰性创建，因此旧存档没有该集合也完全兼容。

地图状态只有三种：

- **visible**：在任一己方城池或在途军队视野内，服务端下发实时地块并刷新快照。
- **explored**：曾可见、当前不可见，下发最后一次快照；客户端在格子上绘制灰雾。
- **unexplored**：从未可见，只下发空地占位和状态，不能泄露地形、设施、军队或任务营地。

## 视野来源与数值

城池半径来自 `game_constants.csv` 的 `city_vision`。军队半径由兵种 `units.csv` 的 `vision` 决定：取数量最多兵种的视野；数量相同则取视野较大者。GM 的兵种数值表可编辑 `vision`，保存后写回 CSV 并镜像到共享配置；`balance_overrides.json` 只作旧版本兼容。

## 行军与探索

`movement` 每推进一格，通过 `vision.Reveal` 写入该时刻军队视野覆盖的快照；返回、驻扎和探索都遵循相同的可见性规则。未探索目标只能发送 `movement.SendExplore`：集结点等级决定允许的未探索深度，军队到达（或在障碍前停下）后立即返程。已探索或可见的空地可发送 `movement.SendGarrison`。

自动探索使用 `movement.SendAutoExplore` 指定一处未探索终点。集结点至少 1 级时，部队可沿路线逐格推进；`vision.Reveal` 为每个自动探索步持久化可重放的首次揭示回执。若该次新揭示范围出现公共 PvE 营地、其他玩家城池或非己方部队，`movement` 立刻掉头返城；否则到达指定终点后返程。任务营地仍是私有信息，不会因自动探索向非任务拥有者泄露。

旧存档无需预处理：旧行军没有 `autoExplore` 时沿原逻辑恢复；`vision_reveal` 在首次自动探索揭示时才创建，缺失时视为没有待重放的回执。因此可直接部署，不需要刷档。

伏击行军使用 `movement.SendAmbush`：目标必须是已探索/可见空地，军队在途期间每格仍会探索，但视野半径固定为 1；抵达后变为驻扎伏击，只能被一格内的其他玩家军队看见。伏击军的隐蔽性由 `movement.ListForeign` 按“单位距离”校验，不会因为敌方城池视野覆盖而暴露。伏击军在抵达前与其他行军相遇时仍按普通野战处理。

`movement.GetMovement` / `movement.List` 仍是路径和实时位置的唯一来源；`HexMap.tsx` 依据 `type: 'explore'` 和 `type: 'ambush'` 绘制探索/伏击虚线路径与部队点。视野模块不拥有军队状态。

地图页的 `world.GetArea` 由 Gateway 注入登录会话的 `playerId`，而不是当前操作村的 `villageId`。因此切换村庄只改变建筑、资源和村庄级行军操作的上下文，不会缩小迷雾来源：当前玩家拥有的每座城池，以及从任意一座己方城池出发的所有在途、驻扎和返程军队，都会共同参与 `visible` 判定。跨村军队视野由 `vision-multivillage.test.ts` 回归覆盖。

地图上的己方军队标记和路径也使用玩家级的 `ListPlayerMovements` 快照，而不是当前村庄级的 `ListMovements`。快照只读返回当前玩家所有己方军队，并带上 `fromVillage` 来源村 id；点击其他村庄派出的军队时，客户端只显示其状态并提供“切换到来源村庄”，真正的召回、续行或其他命令仍通过切村后的 `ownVillage` 路由执行。

## 来袭预警与途中侦察

来袭预警是 `movement` 按 `vision.GetVisibility` 实时派生的临时视图，不属于探索快照，也不属于 `notifications` 战报：

- 只有目标为玩家村庄的掠夺/攻城军，且其当前 `pos` 为 **visible** 时，才进入该村 `movement.List.incomingWarnings`；explored 不产生预警。
- 预警提供抵达倒计时、出发村庄、当前位置与完整路径，但默认不下发 `troops`、`treasures` 或敌军完整 movement。
- 来袭军或守方任一视野源逐格移动、创建或消失时，movement 重算可见状态；变化通过 `movement.IncomingWarningChanged` 推送，客户端只重拉行军快照。该事件不登记到 Notifications，失去视野后页面预警和路径一起消失。
- 村庄、军队、地图页复用 `IncomingWarnings.tsx`；玩家级 `movement.ListPlayer` 聚合所有己方村庄的实时预警，地图额外将当前预警路径绘成红色动态虚线。当前操作村不是受袭村时，侦察按钮会先切换到受袭村再打开编队。

预警中的 `SendIncomingScout` 只允许当前目标村派出侦察兵，冒险者不能执行途中侦察或担任防守侦察兵。主动 `SendScout` 可携带侦察兵或冒险者：冒险者不参与侦察战；目标没有真实侦察兵时可安全取得情报，目标有任一真实侦察兵时冒险者全部被发现并歼灭。侦察军使用来袭路径的逆序路线与敌军相会；同格或同一条边交错都触发侦察战。结算复用普通侦察的反侦察准则：来袭方是守方，每名守方侦察兵消灭一名进攻侦察兵，守方侦察兵自身不损失；来袭军的非侦察兵不参战，仍存活来袭军的 path、速度和 `arriveAt` 不变：

- 进攻侦察方有幸存者：收到当前来袭兵力，并写入来袭 movement 的最新 `incomingIntel`，下一次可见预警展示该情报。
- 进攻侦察方零损失且至少一名存活：定义为“完胜”，额外识别敌军携带宝物；否则宝物保持未知。
- 来袭军出战前拥有侦察兵：来袭方按同一侦察战结算收到反侦察报告；没有侦察兵则无法发现行动，不收到报告。
- 进攻侦察方全军覆没时，携带宝物按普通 PvP 全灭规则归来袭方来源村；进攻方战损走人口伤亡回收，并收到“侦察战失败/全灭”战报；若目标是玩家村，防守方另收一份只包含来袭侦察兵与死亡数量的侦察战报告，不泄露未取得的守军情报。幸存侦察兵返城。

途中侦察的 `ScoutReport` 是正常战报；实时 `IncomingWarningChanged` 不是战报。行军记录新增的 `targetMovementId`、`incomingIntel`、`warningVisibleToTarget` 和 `previousPos` 均为可选字段，旧存档缺失时按无锁定、无情报和不可见状态读取，无需刷档。

## 接口和边界

- `vision.FilterArea`：`world.GetArea` 为已认证玩家查询地图时调用，输出三态 tile 列表。
- `vision.GetVisibility`：供行军模块校验目标状态与未探索深度。
- `vision.Reveal`：供行军模块在逐格推进时持久化探索快照。
- `movement.ListPlayer`（Gateway action `ListPlayerMovements`）：只读返回当前玩家所有来源村的军队快照和所有己方村庄的实时来袭预警，地图用于跨村标记；下令仍走当前村鉴权的行军 action。
- `movement.SendIncomingScout`（Gateway action `SendIncomingScout`）：从当前可见的来袭预警派出仅含侦察兵的拦截部队。
- `movement.IncomingWarningChanged`：可见状态或侦察情报变化的轻量刷新事件；只刷新 UI，不持久化为通知。

视野模块只通过 CommandBus 查询玩家、行军和世界；不直接 import 其他领域模块。客户端不自行判定可见性，只消费服务器下发的 `visibility` 与快照。

## 修改检查

修改视野规则时至少覆盖：城池可见、行军逐格探索、已探索快照冻结、未探索不泄露内容、探索深度限制，以及 GM 覆盖值进入运行时配置。涉及持久字段时优先采用可选字段、缺省值或惰性创建；只有旧存档无法读取时才升级 `SAVE_SCHEMA_VERSION` 并安排刷档。
