# 远弦圣地模块

## 状态边界

`sanctum.ts` 与同 owner 的 `sanctum/` 是 `sanctum` 集合的唯一 owner。它保存单轮活动阶段、参与者已满足的条件、私有线索、公共条件目标、圣地位置、占领者、守卫进度、圣物在途状态及前任占领者记录。新轮次只在显式配置允许时创建；旧档缺少本集合时惰性初始化，不能以刷档作为开启活动的前提。

玩家、村庄、行军、PvE、战斗、宝物库存、任务实例和外交关系仍分别属于既有 owner。圣地模块只能经窄 Command 查询或变更它们，并订阅已发生的 Event 推进条件；它不直接读取其他 owner 的 Store 集合。未来事件延时、守卫截止和可恢复的阶段切换必须登记 Scheduler，重启后由 `resume()` 恢复。

## 生命周期

1. 公共 PvE 或贸易中心按配置掉落 `sanctum_fragment`。拥有残印的玩家可手动接取并在 NPC 对话中唤醒 S23；关闭对话不消耗残印。
2. 第一个成功唤醒者原子成为先发者：停止后续残印掉落、清除其他残印，并获一条仅自己可见的邻近条件提示。其他玩家可通过同一段 NPC 对话手动加入，不能自动完成或获得精确坐标。
3. 加入者任选公共条件完成；每次个人完成都给配置奖励与私有线索。低难一次性目标在首位完成后移除，高难/可重复目标按自身供给与冷却继续出现。条件满足数达到 `sanctum_conditions_required` 后，玩家获得寻迹资格；圣地坐标仍不会全服公开。
4. 合资格玩家到达并调查圣地后，先清理圣地 PvE 守卫，再通过 NPC 对话确认占领。占领驻军成为真实防守方，持有期间的战斗、主动放弃或驻军失守会暂停/重置守卫；占领成功只向活动状态推送，不改变任何外交关系。
5. 守卫完成后，占领军才可取走 `farstring_crest`。圣物随该支真实行军原路返回；携带军败北时圣物回到圣地，不成为胜方战利品。成功归村才永久完成事件、发放圣徽并清理公共活动目标。

联盟成员可增援圣地，但活动争夺允许盟友互相作战；这只是该事件的战斗准入例外，不会创建宣战或改变既有外交关系。前任占领者必须作为主指挥者且满足配置的有效人口比例，才会关闭后来占领者的圣地防守加成，不能用一名旧成员混编规避规则。

## 配置与派生效果

- `sanctum_event.csv`、`sanctum_conditions.csv`、`sanctum_condition_rewards.csv`、`sanctum_puzzles.csv`、`sanctum_puzzle_steps.csv`、`sanctum_clues.csv` 是活动内容事实源，字段见 `config/README.md`。
- `game_constants.csv` 的 `sanctum_*` 参数控制条件数量、守卫时长、圣地防守/远程倍率、前任占领者比例、残印掉落率、谜题/重复条件冷却和专属宝物数值。配置刷新只影响未来创建或新结算的环节，不得跳变已登记的行军/守卫截止时间。
- `pve_targets.csv` 与 `pve_defenders.csv` 定义公共条件营地和圣地守卫；它们是动态实例模板，不能手工写入 `pve_spawns.csv`。
- `treasures.csv` 定义残印、五件条件宝物和最终圣徽；常规效果由宝物/行军/战斗 owner 计算，圣地模块只判断事件阶段与目标是否匹配。
- `quests*.csv` 与 `dialogues.csv` 定义 S23–S29 的任务和文本。任务模块仍拥有任务实例；圣地模块通过任务外部推进接口更新其进度，不能直接修改 `task` 集合。

## 对外协作

`sanctum.GetState` 只返回请求玩家可见的快照：公共条件目标可公开，圣地精确坐标和私有线索只给已经获得它们的玩家。地图与客户端不得从全服推送或其他玩家快照反推坐标。`sanctum.GetCombatModifiers`、`sanctum.GetDefenseSnapshot`、`sanctum.GetMovementModifiers` 只供相应领域 owner 调用，统一返回最终倍率或防守快照；不得把内部占领/条件记录泄露给客户端。

新增公共条件、奖励、谜题或宝物前，先扩展 `infra/config.ts` 的校验和对应 owner 的事件处理，再写 CSV；禁止用未校验的字符串参数绕过条件语义。任何新公开 action、存档字段或 Scheduler key 都按项目版本与变更契约升级、测试和记账。
