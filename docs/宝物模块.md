# 宝物模块（Treasure / 宝物系统）

> 领域模块：`treasure`。对应集合：`treasure`（villageId → TreasureState）+ `treasure_pending`（movementId → PendingTreasure）。
> 配套前端：`packages/client/src/features/treasures/treasures.ts`（宝物面板）+ `packages/client/src/features/reports/reports.ts`（战报中待领取卡片、含归途隐藏）。
>
> **本文档为 Phase J（2026-08-10，commit `04a9972`）上线后的现行状态。** Phase J 之前宝物按「集合（SET）语义」实现：同一宝物只能持有一份，重复获得走「静默售卖/拒绝领取」。Phase J 改为「多重集（MULTISET）语义」：同一宝物可持有多份，每份占 1 槽，效果在 `aggregate` 中累加。

本文档记录宝物系统的服务端实现 + 客户端关键 UI（归途隐藏、栏满替换），供后续维护与扩展参考。

## 1. 职责与定位

每个村庄有**一处宝物栏**（城镇中心自带 1 格基础栏 + 宝库建筑按等级贡献额外格子），宝物存放其中即生效：

1. **被动宝物**（`applyType=passive`，绝大多数）：为村庄提供产出/军事/人口/金币税等加成（见下表）。
2. **即时宝物**（`applyType=instantGold`，如宝箱）：储存时不产生被动效果，玩家主动 `treasure.Use` 一次性发放 `priceGold` 金币后移除。
3. **军队携带**：玩家可把已储存的宝物装上出征/运输军队，在途时城镇失去加成、军队获得加成（movement 模块在出征快照叠加携带效果）。
4. **跨村流转**：返程回家自动入栏；抵达另一村庄转 `deliver` 待处理报告；全歼时按 PvE/PvP 走回收/转交；宝库被拆除走「价值最高留城镇中心 + 其余转 deliver」重分布。

加成对外**只暴露算好的最终值**（铁律#4），由本模块 `aggregate` 计算后经 `commands.send` 推给 economy/population/military。

## 3. 数据模型

存储集合 1：`COLLECTION = 'treasure'`，键为 `villageId`。

```ts
interface TreasureState {
  villageId: string;
  /** 城镇中心格子里的宝物（基础 1 格）。宝物在此即生效（持续累加，多份可并存）。 */
  town: string[];
  /** 宝库(treasury)格子里的宝物（容量 = extraSlots，按 code 分组优先存放点）。 */
  treasury: string[];
  /** 跟随军队的宝物：movementId → { villageId(归属村), codes[] }（铁律#1：本模块拥有）。在途时城镇失去加成、军队获得加成。 */
  carried: Record<string, { villageId: string; codes: string[] }>;
  /** 宝库(treasury)建筑贡献的额外宝物栏槽位（由 building 模块经 treasure.SetSlots 推送镜像）。总槽位 = 城镇中心基础 1 格 + 此值。 */
  extraSlots: number;
  /** 本村是否拥有贸易中心（决定待领取宝物能否「出售」换金币）。由 building 模块经 treasure.SetTradeCenter 推送镜像。 */
  hasTradeCenter: boolean;
}
```

存储集合 2：`COLLECTION_PENDING = 'treasure_pending'`，键为 `movementId`（**注意：是「出征」军队 id，不是「返程」新 id**；movement 模块透传 `outwardId` 解决索引错位，详见 §7.4）。

```ts
interface PendingTreasure {
  movementId: string;       // = 出征军队 id（outwardId），不是返程 id
  villageId: string;         // 归属村庄
  code: string;             // 宝物 code
  name/icon/category/rarity/effectType/effectValue/applyType/priceGold;  // 快照（战报渲染用）
  kind: 'camp' | 'deliver'; // camp=清营掉落（确认即入栏）；deliver=军队送达/宝库拆除（玩家三选一）
  createdAt: number;
  expiresAt: number;        // 超时未确认则调度器自动遗弃；camp 在归村时由 MarkPendingArrived 重置
  arrivedAt?: number;       // 仅 camp：军队到家时间戳；客户端据此前端显示「军队未归」不可领取
  expectedArrivalAt?: number; // 仅 camp：预计军队到家时间戳（rollDrop 占位 now+60s，movement 用真实 arrivesAt 精化）
  fromCarry?: boolean;      // 仅 UI 标记，显示「本村带回」badge；multiset 下重复不再特殊处理
}

interface PendingTreasureView {  // 下发客户端的视图
  ...同 PendingTreasure 字段...
  hasTradeCenter: boolean;   // 客户端据此决定显示「卖出」还是「丢弃」（无贸易中心不能 sell）
  // arrivedAt / expectedArrivalAt / fromCarry 字段含义同上
}
```

聚合效果类型（`aggregate` 返回 + 客户端 `treasure.Changed` 推送）：

```ts
interface TreasureEffects {
  resMult: Partial<Record<'wood'|'clay'|'iron'|'crop'|'gold', number>>; // 各资源加性分数（直接喂 economy.SetRateModifier 的 mult）
  goldMult: number;       // 金币税乘数（人口交税路径单独乘，因 rate modifier 对 gold 无效）
  atkMult: number;        // 军事攻击乘数（防守快照叠加）
  defMult: number;        // 军事防御乘数
  popGrowthMult: number;  // 人口增长乘数
}
```

## 4. 配置

### 4.1 `config/treasures.csv`（宝物定义）

列：`id, code, name, icon, category, rarity, effectType, effectValue, priceGold, dropRate, applyType`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | number | 数字 ID（仅排序/引用，无语义） |
| `code` | string | 宝物代码（**勿改**，持久化引用键） |
| `name` / `icon` | string | 显示名 / 图标基名 |
| `category` | enum | `economic`（经济）/ `military`（军事）/ `social`（社会）/ `special`（特殊） |
| `rarity` | enum | `common` / `rare` / `epic` / `legendary` |
| `effectType` | enum | 见下表 |
| `effectValue` | number | 效果数值（rate 类 = 百分比；`instantGold` = 金币数） |
| `priceGold` | number | NPC 收购价（玩家可卖给 NPC 换金币；栏满溢出时也用此价） |
| `dropRate` | 0-1 | 掉落/出现概率（清营、PvE 战报） |
| `applyType` | enum | `passive`（被动，入栏即生效）/ `instantGold`（即时，use 时一次性发放） |

**`effectType` 聚合规则**（multiset 下「多份相同宝物效果累加」）：

| effectType | 聚合方式 | 说明 |
|------------|---------|------|
| `woodRate` / `clayRate` / `ironRate` / `cropRate` | **加性**：`resMult[k] += frac` | 直接喂 `economy.SetRateModifier` 的 mult |
| `allResRate` | **加性**：四种资源均 `resMult[k] += frac` | 同上 |
| `goldRate` | **加性 + 乘性**：`resMult.gold += frac`，`goldMult *= 1+frac` | 金币无基础产出，rate modifier 对其无效，故双重处理 |
| `atkMult` / `defMult` | **乘性**：`atkMult *= 1+frac` | 作用于防守快照（military.SetTreasureCombatMult） |
| `popGrowth` | **乘性**：`popGrowthMult *= 1+frac` | 人口增长乘数（population.SetTreasureGrowthMult） |
| `instantGold` | 无聚合效果 | 储存时无被动；`treasure.Use` 一次性发放 `effectValue` 金币 |

> **multiset 累加示例**：持有 3 个 `chainsaw`（woodRate +5%）：`resMult.wood = 0.05 + 0.05 + 0.05 = 0.15`（+15%）。
> 持有 2 个 `harvest_totem`（allResRate +12%）：`resMult.wood = resMult.clay = ... = 0.24`（+24%）。
> 持有 2 个 `war_flag`（atkMult +10%）：`atkMult = 1.10 × 1.10 = 1.21`（+21%，复利）。

## 7. 核心流程

### 7.1 效果聚合与推送（`recomputeAndPush`）

```
ensureState(villageId) → 归一化旧档（非数组 town/treasury 兜底为 []，非字符串过滤）
  ↓
aggregate(storedCodes(s)) → TreasureEffects
  ↓
并行发送：
  economy.SetRateModifier  (资源产出加性 mult)
  population.SetTreasureGrowthMult  (人口增长乘数 + 金币税乘数)
  military.SetTreasureCombatMult  (攻防乘数)
```

调用时机：`resume()`（启动时遍历所有村庄）、`recomputeAll()`（GM 覆盖层 reloadConfig 后）、持有/携带/宝库变化后单村推送。

### 7.2 MULTISET 存放与移除

| 操作 | 旧 (SET) 行为 | 新 (MULTISET) 行为 |
|------|--------------|-------------------|
| `storeIfRoom(code)` | 重复 code 拒绝（已持有） | **重复直接入栏**；满则失败 |
| `grant(code)` | 重复拒绝 `already_have` | 重复直接入栏 |
| `replaceTreasure(old, new)` | new 已持有拒绝 | new 已持有也允许（再入一份） |
| `storeCarried` 带回 | 重复份转 `pending(fromCarry)` | 逐份精确扣减，重复份直接入栏（若有空位） |
| `claimPending` take | 重复拒绝 `already_have` | 重复直接入栏；满则 `no_room` |
| `assignToArmy` | 按 code 集合移除 | **按 code 数量精确扣减**（`wantCounts` vs `storedCounts`） |
| `ensureState` | 跨栏去重 (town∩treasury) | 仅做非字符串清理；`town` 和 `treasury` 可同时含同一 code |
| `aggregate(codes)` | `storedCodesUnique` 去重 | `storedCodes`（不去重）→ 多份累加 |

> **核心心智模型变化**：从「宝物种类 = 资源类型」变为「宝物份数 = 资源单位」。每份占 1 格，效果累加。每份的 `effectValue` 决定单份加成；多份按 §4.1 累加规则叠加。

### 7.3 军队携带宝物（`AssignToArmy`）

调用方（movement 或前端）：计算 `maxCarry = min(treasureCarryMaxSlots, floor(总兵力/treasureCarryTroopsPerSlot))`，传入 `codes[]`。

服务端：
1. **预检**：按 `wantCounts` vs `storedCounts` 逐 code 比对数量；任一不足返回 `not_held`。
2. **精确扣减**：维护 `remaining = Map<code, count>`，扫描 `town` 与 `treasury` 数组，按 `remaining` 数量从前往后消费（从 `town` 开始，因为 treasury 是扩容后的优先存放点；逐格命中）。
3. 写 `s.carried[mvId] = {villageId, codes: want}`。
4. `recomputeAndPush`（城镇失去这些宝物加成）；返回 `effects` 让 movement 叠加到出征快照。

> **关键**：multiset 下扣减必须按数量而非「存在性」。旧的 SET 实现 `storedCodes.includes(c)` 检查在 multiset 下会少扣（例如想扣 2 份 chainsaw 但只检查存在性 → 实际只把 town[0] 拿走）。

### 7.4 战斗 / 返程 / 流转（movement 联动）

**清营 / PvE 战斗落幕（`combat.ts → movement.onBattleEnded → treasure.RollDrop`）**：
> **携带宝物必须穿透到战斗（关键！）**：`arriveEngage` 在发出 `combat.Engage` 时务必把 `mv.treasures` 作为 `treasures` 字段转发。Combat 只有拿到携带清单，才会在 `BattleEnded` 回传 `treasures`；否则 `onBattleEnded` 的「全灭→LoseCarried」分支因 `treasures` 恒为空而永不触发，携带记录被孤立、宝物凭空消失（曾因此 bug 丢失 PvP 全灭战利品，已修复，见 §设计要点 - arriveEngage 未转发 treasures 踩坑）。
1. combat 发出 battle end → movement `onBattleEnded` 收到 `payload.movementId`（出征 id）、`payload.treasures`（携带宝物清单，由 arriveEngage 穿透而来）。
2. **rollDrop** 创建 camp pending，`expectedArrivalAt = now + 60_000`（占位）。
3. **scheduleReturn**：创建返程 movement，**新 id**。保存 `outwardId = payload.movementId`（关键！）。
4. **setExpectedArrival**：用返程 movement 的真实 `arriveAt` 覆盖 pending 的 `expectedArrivalAt`（精化 ETA）。
5. **arriveReturn** 触发时：`outwardId = mv.outwardId ?? mv.id` 回链；分别发送 `treasure.StoreCarried`（携带宝物存回）+ `treasure.MarkPendingArrived`（pending 标记归村）。

> **索引关键**：所有「按归属军队索引」的命令（`StoreCarried`、`MarkPendingArrived`、`LoseCarried`）一律用 **outwardId**（出征 id）而非返程 id。`treasure_pending` 同样按 outwardId 索引。详见 §设计要点 - outwardId 修复（outwardId bug 踩坑）。

**携带宝物的出征归属（三态规则）**：

| 场景 | 军队结局 | 宝物归宿 | 触发命令 |
|------|----------|----------|----------|
| 本村之间移动（改驻扎地 / 运输到自己的其他村） | 抵达目的地 | 转交**目的地村庄**（`deliver` 报告） | `treasure.OffloadForeign` |
| 进攻/支援/掠夺/屠城其他玩家村落 | 未被全灭、能返程 | 带回**出发村落** | `arriveReturn → treasure.StoreCarried`（按 outwardId 索引） |
| 进攻其他玩家村落 | 被全灭 | 成为**防守方村落**战利品（`deliver` 报告） | `onBattleEnded` 全灭分支 → `treasure.LoseCarried(mode='pvp', defenderVillage)` |

- **`OffloadForeign`**：抵达另一村庄时，携带宝物转为该村庄的 `deliver` 待领取报告（玩家三选一：收下 / 卖给 NPC / 丢弃）。仅适用于「自己的村落之间」移动。
- **`StoreCarried`**：返程到家（`arriveReturn`）时按 `outwardId` 把宝物存回**出发村落**（multiset 逐份扣减）；用于「进攻他村未被全灭返程」场景。
- **`LoseCarried`**：军队被全歼 → `mode='pve'` 回收到系统池（不入村）；`mode='pvp'` 转交**防守方村庄**作为 `deliver` 报告（即敌方战利品）。

**宝库拆除（`building.Demolished → treasure.SetSlots`）**：当 `next extraSlots < 当前宝物数`：**价值最高（按 priceGold）的 N 份留城镇中心**，**其余转 deliver 报告**（`fromCarry=false`）。由 `treasure.DemolishRedistributed` 推送战报。

### 7.5 确认领取（`ClaimPending`）

| decision | camp | deliver |
|----------|------|---------|
| `take`（默认） | 入栏；满则 `no_room`（不变） | 同 camp |
| `sell` | 需 `hasTradeCenter`；卖 NPC 换 `priceGold` | 同 camp |
| `discard` | 直接移除（不给金币） | 同 camp |

> **multiset 后不再有 `already_have`**：take 在任何情况下都直接入栏（除非满）。`fromCarry` 不再影响 claim 行为，仅 UI 显示「本村带回」badge。

**超时遗弃**：`expiresAt` 到点由 Scheduler 调 `expirePending(movementId)` 自动删除 + 发 `treasure.PendingExpired` 推送。

### 7.6 启动恢复（`resume`）

```ts
async resume() {
  // 1) 遍历所有 treasure 状态重算推送（已 ensureState 归一化）
  for (const s of this.store.all<TreasureState>(COLLECTION)) {
    void this.recomputeAndPush(s.villageId);
  }
  // 2) 修复 pre-MarkPendingArrived 修复前的卡死 pending
  await this.migratePendingsOnResume();
}
```

`migratePendingsOnResume` 处理历史 camp pending 缺 `arrivedAt` / 调度任务丢失：
- 已过期 → 清理
- camp 类未到时、对应 movement 已不存在（军队已归村或全歼）→ 视为已归村，允许领取
- 其余未过期 → 重新登记调度器超时任务

## 8. 设计要点与坑

### 8.1 MULTISET 是核心心智转变

- SET 时代：玩家关心「持有哪哪些种类宝物」、「种类组合的策略性」。
- MULTISET 时代：玩家关心「持有几份宝物」、「每份的数值与可叠加性」。
- UI：持有列表 `codes` 保留重复；同一 code 多份时显示「持有 × N」或多个图标。
- 后续平衡：相同 effectType 的多份叠加需考虑复利（atkMult/defMult 是 `*= 1+frac`）vs 加性（resMult 是 `+= frac`）的差异。

### 8.2 归途隐藏（Phase J 新增）

- **服务端**：`PendingTreasure.expectedArrivalAt`（rollDrop 占位 now+60s → movement 用真实 `arriveAt` 精化）。
- **客户端**：`renderPendingCard` 在 `kind === 'camp' && !arrivedAt` 时返回**简化卡片**：💎 + 「军队带回的宝物·返程中」+ ETA 倒计时（`data-arrives-at`），**不显示**宝物名/效果/稀有度/过期倒计时。
- 抵达后（`MarkPendingArrived` 触发）才渲染完整卡片并启动过期倒计时（`data-expires-at`）。
- `ensureClaimTicker` 同时刷新 `[data-arrives-at]` 和 `[data-expires-at]` 两类倒计时。

### 8.3 索引错位（outwardId bug，已修）

**历史背景**：早期 `treasure_pending` 与 `s.carried` 均按「出征」军队 id 索引，但 `movement.arriveReturn` 调 `treasure.StoreCarried` / `treasure.MarkPendingArrived` 时传的是**「返程」军队新 id**，匹配不到：
1. 携带宝物返程到家后找不到 `s.carried[返程id]` → 永久丢失；
2. camp 掉落 pending 的 `MarkPendingArrived` 匹配不到 → 卡「等待归村」无法领取。

**修复**：`Movement` 新增 `outwardId?: string`；`scheduleReturn` 透传 `p.movementId` 写入；`arriveReturn` 用 `mv.outwardId ?? mv.id` 回链（兼容旧档）。

### 8.4 ensureState 必须 `resume()` 之前能容忍坏数据

旧档可能存在 `town`/`treasury` 缺失、非数组、含 `null`/非字符串等历史损坏。`resume()` → `recomputeAndPush` → `aggregate` 直接 spread 会抛 `is not iterable` 导致**崩溃循环**（每个村庄都崩）。`ensureState` 必须把：
- 非数组 `town`/`treasury` 归一为 `[]`
- 非字符串元素过滤
- 缺字段（`extraSlots`/`hasTradeCenter`/`carried`）补默认值

并把归一化结果写回存档（`dirty` 标志 + `store.set`）。

### 8.5 客户端模板字符串转义陷阱

详见 [`docs/2_2.0设计/07_扩展与代码规范.md`](./2_2.0设计/07_扩展与代码规范.md) 与 PROJECT.md「项目约定与坑」。本模块前端涉及大量动态值拼接（宝物名/效果/数值），统一用 `data-*` 属性携带，handler 内读 `this.dataset.*`，**禁用**字符串拼接转义引号。

### 8.6 forEach 回调内禁止 `continue`

`[].forEach((x) => { if (...) continue; ... })` 在 TS 严格类型下报 `TS1107: Jump target cannot cross function boundary`。应改用 `return`（箭头函数 return 等价于 forEach 的 continue）。Phase J 修复过 `reports.ts` 的 `ensureClaimTicker` 第二处 forEach。

### 8.7 arriveEngage 必须转发 `mv.treasures`（PvP 全灭宝物消失）

**症状**：带宝物进攻其他玩家村落，军队被全灭后宝物凭空消失（既不在进攻方也不在防守方）。

**根因**：`movement.arriveEngage` 发出 `combat.Engage` 时**未传 `treasures` 字段**。Combat 不知道这支军队携带了宝物 → `combat.BattleEnded.treasures` 恒为 `[]` → `movement.onBattleEnded` 的「全灭→`treasure.LoseCarried`」分支因 `treasures.length === 0` 而**跳过** → `s.carried[outwardId]` 携带记录被孤立、再无消费者 → 宝物永久丢失。

**修复**：`arriveEngage` 中 `const carried = mv.treasures && mv.treasures.length > 0 ? mv.treasures : [];`，并在 `combat.Engage` payload 加 `treasures: carried`。自此 `BattleEnded` 回传真实携带清单，`onBattleEnded` 全灭分支得以调用 `LoseCarried(mode='pvp', defenderVillage)` 把战利品转交防守方。

**锁定的回归测试**：`packages/server/src/test/pvp-treasure.test.ts`（2 例：PvP 未被全灭→宝物带回出发村；PvP 被全灭→宝物成为防守方战利品）。

> 教训：**凡「军队携带 X 进入战斗」的字段，都必须在 `arriveEngage → combat.Engage` 链路显式穿透**，否则战斗结算侧永远拿不到，相关分支静默失效。
