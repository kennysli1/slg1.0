# 贸易模块（Trade / 贸易中心）

> 领域模块：`trade`。对应建筑：`tradecenter`（贸易中心，城外建筑 id=18）。
> 配套前端：`packages/client/src/features/trade/tradecenter.ts`（详情页为居中抽屉）。

本文档记录贸易系统的服务端实现，供后续维护与扩展参考。

## 1. 职责与定位

每个村庄可建一处「贸易中心」。中心提供三件事：

1. **NPC 订单池**：玩家用金币买资源 / 卖资源换金币，**即时交付**（无需等待商队）。
2. **玩家挂单**：玩家创建贸易订单（提供资源 + 想要资源，可含金币），供**视野半径内**的其他村庄接受。
3. **玩家接单**：接受他人订单 → 双方各派一支商队运送货物 → 消耗各自贸易路线，商队返回家园后回收路线。

设计上整体**镜像 `mercenary`（雇佣兵营地）模块模式**：中心等级决定容量/视野/刷新；状态存于 `trade` 集合；通过 `commands.send` / `bus.emit` 与其他模块交互，不持有其他模块的内部状态。

## 3. 数据模型

存储集合：`COLLECTION = 'trade'`，键为 `villageId`。

```ts
interface TradeCenterState {
  villageId: string;
  level: number;                  // 缓存自 building.GetBuildingLevel，升级时刷新
  npcOrderPool: NpcOrder[];       // 当前 NPC 订单池
  storedRefreshes: number;        // 已囤积的手动刷新次数
  nextRefreshAt: number;          // 下次自动刷新时刻(ms)
  tradeRoutesUsed: number;        // 在途商队占用的贸易路线数
  createdOrders: PlayerOrder[];   // 本村挂出的玩家订单
  taskId?: string;                // 自动刷新定时任务 id
}

interface NpcOrder {
  id: string;
  give: Record<string, number>;   // 村庄能拿到的资源（NPC 给玩家）
  want: Record<string, number>;   // 村庄需支付的资源（玩家付 NPC，含 gold）
  distance: number;               // 来源距离(格)，受 viewRadius 限制
  expiresAt: number;
}

interface PlayerOrder {
  id: string;
  villageId: string;              // 创建者村庄
  fromXY: Hex;                    // 创建者坐标快照（接受方测距用）
  give: Record<string, number>;   // 创建者提供的资源（含金币）
  want: Record<string, number>;   // 创建者想要的资源（含金币）
  routesNeeded: number;           // 创建者所需路线数 = ceil(give单位数 / 路线运力)
  createdAt: number;
  ttlAt: number;                  // 过期时刻
}
```

> 另有一个**全局玩家挂单索引** `private orders = new Map<string, PlayerOrder>()`（orderId → 订单），用于快速可见性查询与生命周期管理。`resume()` 时从各村的 `createdOrders` 重建该索引。

### 4.2 `config/game_constants.csv`（trade_* 全局常量）

| 常量 | 默认 | 含义 |
|------|------|------|
| `trade_route_capacity` | 500 | 每条贸易路线可运送的货物**单位数**（5 种资源各计 1 单位） |
| `trade_caravan_speed` | 12 | 商队速度（倍率，独立于军队行军速度） |
| `trade_npc_gold_per_resource` | 0.5 | NPC 计价基准：每单位资源价值多少金币 |
| `trade_npc_sell_margin` | 0.8 | 玩家**卖给** NPC 时的折价系数（拿全额金币 × 此系数） |
| `trade_order_max_per_village` | 5 | 每村最多同时挂出的玩家订单数 |
| `trade_order_ttl_sec` | 86400 | 玩家订单存活时间（秒），过期自动下架 |

> 客户端经 `app/config.ts` 暴露上述常量；服务端在 `meta.ts` 白名单 + `infra/config.ts` 解析。

## 5. 命令（MANIFEST.publicActions）

全部 `ownVillage: true, needAuth: true`：

| 公共动作 | 命令名 | 入参 | 说明 |
|---------|--------|------|------|
| `GetTradeCenter` | `trade.GetCenter` | `{villageId}` | 拉取中心全量状态（NPC 订单 / 可见玩家订单 / 我的订单 / 路线余量 / 金币） |
| `RefreshTrade` | `trade.Refresh` | `{villageId}` | 手动刷新：消耗 1 次 `storedRefreshes`，立即重 roll NPC 订单池 |
| `AcceptNpcOrder` | `trade.AcceptNpc` | `{villageId, orderId}` | 接受 NPC 订单，**即时**扣 `want` 给 `give`（含金币） |
| `CreateTradeOrder` | `trade.CreateOrder` | `{villageId, give, want}` | 创建玩家挂单（路线运力校验 + 数量上限 + TTL） |
| `AcceptPlayerOrder` | `trade.AcceptPlayer` | `{villageId, orderId}` | 接受他人订单 → 派双向商队（资源预检 + 退款 + 路线回收） |
| `CancelTradeOrder` | `trade.CancelOrder` | `{villageId, orderId}` | 撤销自己挂出的订单 |

事件推送：`trade.CenterUpdated → TradeCenterUpdated`（仅含 `villageId`，客户端据此 `refreshTradeIfOpen()` 重拉）。

## 6. 跨模块交互

| 方向 | 调用 | 用途 |
|------|------|------|
| trade → building | `building.GetBuildingLevel({kind:'tradecenter'})` | 读中心等级（唯一口径） |
| trade → world | `world.GetTileByRef({refId, kind:'village'})` | 取村庄坐标（测距） |
| trade → economy | `economy.TrySpend` / `economy.Grant` / `economy.GetResources` | 扣/给资源（含金币）、读金币余额 |
| trade → movement | `movement.SendCaravan` | 派商队运货 |
| movement → trade | `movement.CaravanReturned {villageId, routesFreed}` | 商队返家 → 回收贸易路线 |
| building → trade | `building.Built` / `building.Upgraded`（`kind==='tradecenter'`） | 确保中心状态存在 / 刷新等级与刷新排程 |
| app → trade | `wipeSingleVillage` | 丢村/删号时清空该中心与挂单索引条目 |

## 7. 核心流程

### 7.1 NPC 订单（即时交易）
- `rollNpcOrder`：随机选一种资源（wood/clay/iron/crop），随机交易量随等级放大（`200 + rand(400 + level*120)`），按 `tradeNpcGoldPerResource` 计价；50% 概率「玩家卖给 NPC（拿折价金币）」、50%「玩家向 NPC 买（付全额金币）」。
- **自动刷新** `refreshTick`：`nextRefreshAt` 到点 → 重 roll 整池 + `storedRefreshes = min(上限, +1)` + 重排程。
- **手动刷新** `refresh`：消耗 1 次 `storedRefreshes`，立即重 roll 整池（保持 `nextRefreshAt` 不变）。
- **接受** `acceptNpc`：先 `economy.TrySpend(want)` 后 `economy.Grant(give)`，即时生效；成功后从池移除该单并补一条新单保持池满。

### 7.2 玩家挂单（CreateTradeOrder）
1. 清洗 `give`/`want`（仅含 wood/clay/iron/crop/gold 的正整数，空则拒绝）。
2. **路线运力校验**：`giveUnits = Σ give 单位数`，`routesNeeded = ceil(giveUnits / tradeRouteCapacity)`；若 `> availableRoutes` → 失败（返回 `routesNeeded`/`available`）。
3. **数量上限**：已达 `tradeOrderMaxPerVillage` → 失败。
4. 记录创建者坐标快照，`ttlAt = now + tradeOrderTtlSec*1000`，写入 `createdOrders` 与全局 `orders` 索引。

### 7.3 玩家接单（AcceptPlayerOrder，双向商队）
1. 从全局 `orders` 取单；校验非己单、未过期、距离 ≤ 接受方 `tradeViewRadius`。
2. 双方路线校验：创建者需 `order.routesNeeded` 条空闲路线；接受者需 `ceil(Σ want 单位数 / 路线运力)` 条。
3. **资源预检**（避免半扣）：创建者的 `give`、接受者的 `want` 在各自村庄都必须够。
4. **先扣后给 + 失败退款**：扣创建者 `give` → 扣接受者 `want`（失败则退还原 `give`）→ 派创建者商队（失败则双向退款）→ 派接受者商队（失败则双向退款）。
5. 扣减双方 `tradeRoutesUsed`，`removeOrder` 下架订单，`emitUpdated` 双方。

### 7.4 贸易路线回收
- 派商队时 `tradeRoutesUsed += 所需路线数`（即时占用）。
- 商队抵达目标并自动返程，**返家时** movement 发 `movement.CaravanReturned {villageId: homeVillage, routesFreed}` → `recoverRoutes` 把 `tradeRoutesUsed` 减回。

> 关键：路线是「占用→返家回收」，不是「接单时永久扣」。若某村路线全占满，需等商队回来才能再接/挂单。

## 8. 设计要点与坑

- **NPC 订单即时交付、玩家订单靠商队**：前者无路线占用、无延迟；后者按路线运力约束，受距离与 TTL 限制。
- **`insufficient_routes` 同时返回 `routesNeeded`/`available`**，前端可据此提示「差几条路线」。
- **退款顺序**：任何一步 `TrySpend`/`SendCaravan` 失败都回退此前已扣资源，保证不会出现「钱扣了货没发」。
- **`resume()`** 必须重建全局 `orders` 索引、清理过期单、重排自动刷新定时——重启后订单与刷新不丢失。
- 视图距离用 `hexDistanceWrapped`（环形地图），需 `worldW/worldH`（默认 41×41）。
