# 雇佣兵营地模块（Mercenary / 雇佣兵营地）

> 领域模块：`mercenary`。对应建筑：`mercenarycamp`（雇佣兵营地，城外建筑 id=17）。
> 配套前端：`packages/client/src/features/army/mercenary.ts`（招募页为居中抽屉）。

本文档记录雇佣兵营地系统的服务端实现 + 客户端抽屉（含 2026-08-10 新增的「拆除雇佣兵营地」危险操作），供后续维护与扩展参考。

## 1. 职责与定位

每个村庄可建一处「雇佣兵营地」。营地提供三件事：

1. **NPC 雇佣名单**：周期性刷新一组可雇佣兵种，玩家用金币购买名单上的兵种。
2. **永久写入 military.troops**：雇佣兵 `popCost=0 / upkeep=0`，直接入 troops 自动参战、自动零副作用。
3. **手动刷新 + 自动囤积**：玩家可消耗存储的刷新次数手动重 roll；不手动的话，每次自动刷新时 +1 存储（存满为止），让低等级营地也能「攒刷新卡」。

设计上**镜像 `trade`（贸易中心）模块模式**：等级决定容量/刷新间隔；状态存于 `merc` 集合；通过 `commands.send` / `bus.emit` 与其他模块交互，不持有其他模块内部状态。

## 3. 数据模型

存储集合：`COLLECTION = 'merc'`，键为 `villageId`。

```ts
interface MercenaryCampState {
  villageId: string;
  /** 营地等级（缓存自 building.GetBuildingLevel；升级时刷新）。 */
  level: number;
  /** 当前可雇佣名单（兵种 code 列表）。 */
  offers: string[];
  /** 已存储的刷新次数（手动刷新消耗）。 */
  storedRefreshes: number;
  /** 下次自动刷新时刻（ms）。 */
  nextRefreshAt: number;
  /** 自动刷新定时任务 id（用于重启恢复时重新登记）。 */
  taskId?: string;
}
```

雇佣兵池（来自 `units.csv`）：所有 `isMercenary=1` 的兵种。营地每次刷新从中随机抽 `mercCount` 个不重复 code。

`GetMercCamp` 返回给客户端的视图：

```ts
{
  built: boolean;           // 是否有营地（未建时 false）
  level: number;
  offers: Array<{
    code, name, icon, form,
    meleeAtk, rangedAtk, meleeDef, rangedDef,
    speed, carry, goldCost,
  }>;
  storedRefreshes: number;
  maxStored: number;
  refreshSec: number;
  nextRefreshAt: number;
  gold: number;             // 玩家当前金币（用于按钮置灰）
}
```

## 4. 配置

### 4.1 `config/merc_camp.csv`（逐级参数）

列：`level, refreshSec, mercCount, maxStoredRefreshes`

| 等级 | 刷新间隔(秒) | 每次刷新名额 | 存储上限 |
|------|------------|------------|---------|
| 1 | 3600 | 3 | 1 |
| 2 | 3300 | 3 | 1 |
| 3 | 3000 | 4 | 2 |
| 4 | 2700 | 4 | 2 |
| 5 | 2400 | 5 | 3 |
| 6 | 2100 | 5 | 3 |
| 7 | 1800 | 6 | 4 |
| 8 | 1500 | 6 | 5 |
| 9 | 1200 | 7 | 6 |
| 10 | 900 | 8 | 8 |

缺级兜底：解析时从已配置的最高有效级向下复制，保证任意等级都能取到参数。

### 4.2 `config/units.csv` `isMercenary` 字段

兵种定义中 `isMercenary=1` 表示可被营地随机抽出。其它兵种（玩家训练/野怪等）不在营地池中。

兵种 `goldCost` 字段即雇佣价（玩家花多少金币雇一个该兵种）。

## 5. 命令（MANIFEST.publicActions）

全部 `ownVillage: true, needAuth: true`：

| 公共动作 | 命令名 | 入参 | 说明 |
|---------|--------|------|------|
| `GetMercCamp` | `mercenary.GetCamp` | `{villageId}` | 拉取营地状态（名单 + 存储次数 + 倒计时 + 金币） |
| `RefreshMercCamp` | `mercenary.Refresh` | `{villageId}` | 手动刷新：消耗 1 次 `storedRefreshes`，立即重 roll 名单 |
| `HireMerc` | `mercenary.Hire` | `{villageId, code}` | 雇佣：扣金币 → 写 military.troops → 消费该 offer |

事件推送：`mercenary.CampUpdated → MercenaryCampUpdated`（仅含 `villageId`，客户端据此 `refreshMercCampIfOpen()` 重拉）。

## 6. 跨模块交互

| 方向 | 调用 | 用途 |
|------|------|------|
| mercenary → building | `building.GetBuildingLevel({kind:'mercenarycamp'})` | 读营地等级（唯一口径） |
| mercenary → economy | `economy.TrySpend({cost: {gold: goldCost}})` | 雇佣扣金币 |
| mercenary → economy | `economy.GetResources` | 读金币余额（用于按钮置灰） |
| mercenary → military | `military.AddMercenaries({units: {code: 1}})` | 永久写入雇佣兵 troops |
| building → mercenary | `building.Built` / `building.Upgraded`（`kind==='mercenarycamp'`） | 确保营地状态并刷新参数 |
| app → mercenary | `wipeSingleVillage` | 丢村/删号时清空该营地 |

## 7. 核心流程

### 7.1 营地生命周期（`ensureCamp`）

`building.Built` 或 `building.Upgraded` 事件触发：
- **首次建造**：`level = GetBuildingLevel`，`offers = rollOffers(level)`，`nextRefreshAt = now + refreshSec*1000`，`storedRefreshes = 0`，登记 Scheduler 定时任务。
- **升级**：更新 `level`，按新 `refreshSec` 重排下次自动刷新；**保留当前名单与已存储次数**（不强行重 roll，玩家可以继续用现有名额）。

> 设计取舍：升级不重 roll，避免玩家损失「即将雇的好兵种」。存储次数保留避免浪费。

### 7.2 自动刷新（`refreshTick`）

到 `nextRefreshAt` 时：
1. 重 roll 名单（`rollOffers(level)`）。
2. `storedRefreshes = min(maxStoredRefreshes, storedRefreshes + 1)`（自动囤积）。
3. 按新 `refreshSec` 重排下次定时任务。
4. `emitUpdated` 推送 `mercenary.CampUpdated`。

### 7.3 手动刷新（`refresh`）

消耗 1 次 `storedRefreshes`，立即重 roll 名单。**不改变** `nextRefreshAt`（即不打断自动刷新节奏）。

### 7.4 雇佣（`hire`）

1. 校验：`offers.includes(code)`、`config.units[code].isMercenary`。
2. `economy.TrySpend({cost: {gold: goldCost}})`；失败返回 `spend_failed`。
3. `military.AddMercenaries({units: {code: 1}})` 永久写入。
4. 从 `offers` 移除该 code（**同一名额不可重复雇**，玩家可等下次刷新或手动刷新）。
5. `emitUpdated` 推送。

雇佣兵 `popCost=0 / upkeep=0` → 自动零副作用、自动参战。这是与玩家训练兵种的**本质差异**：训练兵要占人口、耗粮、维护；雇佣兵零负担但需金币。

## 8. 设计要点与坑

### 8.1 与 trade 模块的对称

镜像 `trade.ts` 的模式：等级决定容量/刷新间隔；状态存单一集合；Scheduler 注册自动刷新任务；事件推送客户端重拉；GM 表登记。扩展时可参照 trade 的实现。

### 8.2 升级不重 roll

`ensureCamp` 升级路径显式保留 `offers` 与 `storedRefreshes`，避免玩家失去「即将雇的好兵种」。**这是与 trade 不同的地方**：trade 升级也是保留（NPC 订单池照常运转），merc 升级也是保留。

### 8.3 雇佣兵的零负担特性

雇佣兵 `popCost=0 / upkeep=0`（由 `units.csv` 字段决定），写入 `military.troops` 后自动参战、自动零副作用。这是设计目标：让金币成为「跳过粮/人口训练」的快通道，但要消耗金币（不能滥用）。平衡时注意 `goldCost` 与同等训练兵种的实际养成成本（金币+时间）的比例。

### 8.4 拆除雇佣兵营地（2026-08-10 新增）

- **服务端**：营地拆除走 `building.Demolish`（已支持非城镇中心建筑）。`building.Demolished` 事件触发 → 营地状态由 `wipeSingleVillage` 或 building 模块清理；已雇佣兵种**仍属本村军队**（不收回），下次 `military.GetTroops` 仍返回。
- **客户端**：`openMercenaryCamp(act, slotId?)` 接收 `slotId`；抽屉底部新增「危险操作·拆除雇佣兵营地」按钮（二级确认，委托 `building.Demolish`）。
- 调用方：village.ts 的两个打开路径（`openBuilding(slotId)` 与 `[data-bld-slot]` 整卡点击）均统一透传 `slotId`。

> **注意**：拆除前已雇的雇佣兵不收回，玩家可继续使用。这是有意设计：避免拆除造成军队意外损失。

### 8.5 启动恢复（`resume`）

```ts
resume() {
  for (const s of this.store.all<MercenaryCampState>(COLLECTION)) {
    const delay = Math.max(0, s.nextRefreshAt - this.now());
    s.taskId = scheduler.schedule(delay, () => refreshTick(s.villageId), 'mercenary:<villageId>', 'village:<villageId>');
    store.set(COLLECTION, s.villageId, s);
  }
}
```

按 owner 去重（`mercenary:<villageId>`），重启后自动刷新节奏不丢失。

## 9. 前端

`packages/client/src/features/army/mercenary.ts` 提供 `openMercenaryCamp / refreshMercCampIfOpen / closeMercenaryCamp`：
- 详情页为**居中抽屉**（`drawer drawer--opening merc-drawer drawer--center`），与贸易中心保持一致风格。
- 渲染：金币持有 / 存储刷新 / 倒计时 / 可雇佣名额卡片（每张带雇佣按钮，金币不足置灰）。
- **2026-08-10 新增**底部「危险操作·拆除雇佣兵营地」按钮（slotId 必传才显示）。
- `bootstrap.ts` 的 `onPush` 收到 `MercenaryCampUpdated` 即调 `refreshMercCampIfOpen()` 重拉。
