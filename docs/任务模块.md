# 任务模块

## 事实源与职责

任务定义只在 `config/quests*.csv`：任务线、任务节点、条件、目标、效果、关系边六张表。`infra/config.ts` 读取、校验并编译它们；`modules/tasks.ts` 按任务 `scope` 保存任务实例、事件推进、交付和任务营地，客户端通过 `task.GetPlayerState` 将任务分成全局任务与当前村庄任务。NPC 对话定义单独位于 `config/dialogues.csv`，由 `modules/dialogues.ts` 按任务代码和触发点创建一次性 session，不把对话或当前回复写进存档。宝物、PvE、贸易等跨模块结果经既有 Event/窄命令进入任务模块，不能反向写任务状态。

任务是玩家工作区的一部分而不是村庄页面的附属栏。主线任务默认 `scope=global`，全局支线也可显式配置为 `global`；每日任务和当前四个支线任务（s1–s4）为 `scope=village`。全局实例固定存于玩家第一座村（主城）作为锚点，但任务营地在激活/接取时记录 `spawnVillageId`，并以该村当时的坐标生成一套唯一营地；全局任务从任意己方村清理时仍更新同一实例。村庄任务只读取并写入其绑定村，允许其它己方村出兵，但进度、任务掉落报告、就绪状态和奖励领取均回写绑定村。聚合快照的 `global` 区块只出现一次，`villages` 区块按村切换；客户端把全局营地合并到玩家所有村的地图缓存，避免任务卡与地图各自保留一套坐标。客户端执行动作时使用当前选中的村处理全局任务，而不是在领奖时临时改投当前村。待处理报告也携带奖励收件村标识。

任务页的菜单层级固定为：全局任务 / 村庄任务（一级）→ 主线、支线、日常（二级）→ 具体任务（三级）。没有任务内容的二级分类自动隐藏，具体任务默认展开。全局区包含主线、全局支线、全局日常和王国任务；村庄区只显示当前操作村的支线和日常。M1 是唯一建村自动激活的主线，后续主线满足前置后进入 `offeredMain`，必须由玩家手动接取，接取后才创建任务实例、营地或其他目标。任务页顶部复用 `VillageList`，切换村庄后只切换村庄区，不能查看、接取或操作其他村的村庄级任务。同一玩家的一次性支线只能由一个村接取；接取时会从该玩家其他村的可接取列表移除。日常任务仍在酒馆/任务页显示和接取，但不计入导航栏、一级/二级菜单的可接取提醒；非日常任务的三级菜单即使展开，任务摘要仍保留“可接取”提醒标记。

GM 运维命令 `task.GmResetAll` 只清空所有玩家和村庄的任务状态及任务营地，并重新激活各玩家主城的 M1；不修改资源、建筑、军队、科技、声望或地图其他实体。

任务页签的数字提醒统计玩家聚合快照中 `offeredMain`、`offeredSide` 和非日常 `offered` 的可接受任务数量；酒馆日常仍显示和可接取，但不计入提醒。进行中的任务和待领取奖励不计入。一级/二级菜单折叠时，在对应摘要显示可接受任务数量；展开后非日常三级任务条目仍保留提醒，日常条目不显示提醒。各级 `details` 的展开状态按玩家 id 写入浏览器本地存储，重新进入任务页时恢复；存储不可用时仅退化为本次页面状态。

当前实例会保存 `lineCode` 和 `definitionRevision`；旧实例缺失这两个字段时由任务代码的当前定义惰性补齐。任务定义结构变化属于存档契约变化，需升 `SAVE_SCHEMA_VERSION` 并在 CHANGELOG 标 `[需刷档]`。

## 图模型

```text
quest_lines ──入口──> quests
                         ├── quest_conditions  （何时出现）
                         ├── quest_objectives  （如何达成）
                         ├── quest_effects     （各阶段效果）
                         └── quest_edges ────> 下游 quests
```

- `requires` 边：来源任务交付后，终点才可出现；校验禁止循环。
- `success_unlock` / `failure_unlock`：记录显式分支关系，供审查与后续多阶段运行时扩展；已有特殊任务仍保留其既有事件处理器，避免改表时改变已上线行为。
- 任务可有多条条件、目标和效果。现有运行时将当前单目标玩法编译为兼容定义；新目标/效果类型须先在运行时注册，再写进 CSV。

## 当前主线目标（M1–M6）

主线均为全局任务，实例锚定主城；执行时可从当前己方村庄操作，奖励发放到最后实际执行目标的村庄。M1 仍在建村时自动激活，其余主线满足关系边后进入可接取状态并须手动接受。

| 任务 | 名称 | 目标 | 配置目标类型 |
| --- | --- | --- | --- |
| m1 | 初来乍到 | 修复新村四块被破坏的资源田 | `repair_buildings` |
| m2 | 大兴土木 | 接取后在主城建造任意 2 栋城内建筑 | `build_buildings`，参数 `inner:2` |
| m3 | 人丁兴旺 | 主城总人口达到 30 | `population_reached`，参数 `30` |
| m4 | 排除威胁 | 接取村附近生成 1 个老鼠窝强度 PvE 营地并清理 | `clear_camp`，参数 `rats:1` |
| m5 | 那边有什么？ | 累计探索 100 格；城镇初始视野也计入 | `explore_tiles`，参数 `100` |
| m6 | 国库充盈 | 主城当前拥有 100 金币，不消耗金币 | `resource_owned`，参数 `gold:100` |

门槛类目标由建筑、人口、资源和战争迷雾模块的权威快照推进，任务只保存进度和就绪状态，不复制这些模块的数据。M2 额外保存接取瞬间的城内建筑基线，只累计接取后完成的新建建筑；已完成的建造进度不会因后续拆除倒退。`explore_tiles` 统计玩家已探索快照与当前城镇/行军视野的并集，因此新账号开局即可拥有初始视野进度。

每个主线在 `config/dialogues.csv` 都必须同时有 `<code>_accept`（接取）和 `<code>_deliver`（交付）两行。模板可以保持 NPC、文本和回复为空；配置校验会阻止新增主线遗漏任一行。交付对话由 `task.Deliver` 与奖励明细一起返回，GM 填写后在领奖弹窗展示，空白模板不会弹出额外内容。M1 现有自动接取对话文本保持不变。

## 现有任务的特殊处理

`村民的请求`、`调查坐标`、`耀武扬威`涉及 NPC/任务营地、随军军旗或待处理宝物。这些动态对象的生命周期仍由 `tasks.ts` 中的命名处理器拥有；CSV 描述触发、目标、奖励和关系，处理器负责根据玩家实际选择推进状态。不得把坐标、营地 id、宝物实例 id 等玩家态写回配置表。

幸福村是不可重生的 PvE NPC；被战斗清空时由 `combat` 通过 `pve.Remove` 立即移除实体，统一触发 `pve.TargetRemoved`，因此仍在前往该村的商队会从服务端记录的当前行军进度自动返程。任务卡片展示完成、失败及多阶段分支的资源、宝物和声望结果；S3 完成结算 -1 声望，S4 释放结算 +2 声望，收纳分支失败结算 -2 声望。S4 释放后，任务交付命令返回的奖励对象同时包含资源奖励（500 金币）、声望和宝物，客户端据此完整展示领奖明细。

任务营地默认不因战败而推进或失败；战败事件只记录战报并保留任务营地，若旧存档或并发结算导致实体暂时消失，任务模块会按任务快照坐标恢复。只有任务定义明确增加战败失败规则时，才允许改变这一生命周期；当前任务图没有此类任务。

地图选中任务营地时，客户端从任务实例快照派生并展示关联任务名称、任务说明、全局/村庄任务类型和清理进度；单独的地图标记推送不得覆盖掉这份关联信息。

## GM 工作流

`/gm/quest-modules` 可分别编辑六张任务图表；“保存全部模块”会复制完整配置到临时目录，以 `loadGameConfig` 做全图校验，失败不会写入任何一张线上表。`/gm/dialogues` 专门编辑 NPC 名称、文本和玩家回复选项，同样先在临时配置目录校验再热重载。`/gm/quest-graph` 按任务线显示每个节点的条件、目标、效果、入边和出边，用于提交前审查。

GM 修改是运行配置修改，不会自动提交 Git。需要长期保留的数值/结构调整，应将同样的 CSV 改动带入功能分支、通过验证并合并发布；否则下一次代码发布会以仓库版本为准覆盖。

## 新增或改造任务的步骤

1. 先确定所属任务线；没有合适任务线才在 `quest_lines.csv` 增加一行。
2. 在 `quests.csv` 建立稳定 code，禁止复用已删除任务的 code。
3. 分别添加条件、目标、效果和关系边，并在 GM 图检查所有引用。
4. 若引入新的目标、条件或效果 `kind`，先在 `config.ts` / `tasks.ts` 增加类型、校验和测试；不要用字符串绕过校验。
5. 为触发、放弃、完成、交付、重启恢复和旧存档各补一条服务器测试；涉及宝物/营地时还要覆盖归城、满栏和目标消失。
6. 更新 `config/README.md`、CHANGELOG 和本页长期有效结论，按 `CLAUDE.md` 完成验证、PR、合并与部署。
