# 部署手册 · 腾讯云轻量应用服务器（实操版）

> 目标：把游戏部署到公网，你和朋友能通过 `http://你的公网IP:8080` 一起玩。
> 系统：Linux。数据用 JSON 文件持久化（无需装数据库）。进程用 pm2 保活。
> 标 **【你做】** 的需你在服务器/本地操作；命令可直接复制。遇到任何报错把屏幕内容发我。

---

## 步骤 0 · 先准备（控制台操作）【你做】

1. 登录腾讯云控制台 → 轻量应用服务器 → 你的服务器。
2. 记下 **公网 IP**：`____________`
3. 「防火墙」标签 → 添加规则：放行 **TCP 8080**（应用端口）。SSH 的 22 通常已开。
4. 用「登录」按钮打开网页终端，敲 `cat /etc/os-release`，看是 Ubuntu/Debian 还是 CentOS。

---

## 步骤 1 · 服务器装 Node.js 20【你做，在服务器终端】

**Ubuntu / Debian：**
```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v        # 应显示 v20.x
```

**CentOS / 腾讯云 OpenCloudOS：**
```bash
curl -fsSL https://rpm.nodesource.com/setup_20.x | sudo bash -
sudo yum install -y nodejs
node -v
```

装 pm2（进程守护，开机自启+崩溃重启）：
```bash
sudo npm install -g pm2
```

## 步骤 2 · 初始化生产根目录

生产服务器不 clone 仓库，也不在服务器上执行 `git pull`。GitHub 是唯一代码事实源，发布脚本会创建以下结构：

```text
~/kow/
├── releases/<commit-sha>/   # 不可变代码版本
├── current -> releases/...  # PM2 当前运行版本
├── shared/data/             # 正式存档
├── shared/logs/             # 正式日志
└── backups/                 # 首次迁移时保留旧 Git 元数据
```

只需提前创建根目录：

```bash
mkdir -p ~/kow
```

如需在服务器临时调试，必须另建 `~/kow-dev`；禁止修改 `~/kow/current` 或任一 release。

## 步骤 3 · 首次发布

在本地仓库确认目标改动已经通过 PR 合入远程 `main`，然后执行 `npm run deploy:prod`。脚本会在本地隔离验证，在服务器 release 目录构建。

---

## 步骤 4 · 确认进程保活

```bash
pm2 status
pm2 startup  # 首次配置机器时，按提示再执行它输出的一条命令
```
`deploy:prod` 已经自动执行 `pm2 startOrReload` 和 `pm2 save`，日常发布不需要手工启动。
查看状态/日志：
```bash
pm2 status                         # 看是否 online
pm2 logs kow                  # 看实时日志（Ctrl+C 退出查看）
```

---

## 步骤 5 · 发布与验收

功能分支提交只做本地验证。代码通过 PR 合并并推送远程 `main` 后，执行：

```bash
npm run deploy:prod
```

可以从任意本地分支运行这条命令，但脚本只读取远程 `origin/main` 的 SHA，在临时 worktree 安装、测试、构建并打包该提交。当前分支、未提交内容和本地 main 不会进入生产包。

远端构建完成后先原子切换 `current`，再完成本机与公网验收。验收覆盖 `/health`、首页、JS/CSS、关键美术和 WebSocket，并要求 `/version` 返回 `releaseBranch=main` 和目标 `releaseCommit`。任何一步失败都会把 `current` 切回上一个 release；正式存档和日志位于 `shared/`，不参与代码回滚。

首次从旧目录迁移时，脚本会复制原 `data/` 和 `logs/` 到 `shared/`。公网验收成功后，旧 `.git` 会移动到 `backups/legacy-git-<时间>`，因此在生产根目录运行 `git status` 应提示“不是 Git 仓库”，不会再出现伪造的未提交改动。

## 日常运维速查

| 操作 | 命令 |
|------|------|
| 看运行状态 | `pm2 status` |
| 看日志 | `pm2 logs kow` |
| 重启 | `pm2 restart kow` |
| 停止 | `pm2 stop kow` |
| 更新代码后重新部署 | 合并并推送远程 main 后运行 `npm run deploy:prod` |
| 改游戏数值 | 本地功能分支修改 → PR 合入 main → `npm run deploy:prod` |

> **存档在哪**：`~/kow/shared/data/game.json`。备份它就是备份整个游戏世界。重启和代码回滚都不丢数据。

---

## GitHub 连接说明

生产服务器不再访问 GitHub。`deploy:prod` 在发起部署的本地机器读取远程 `origin/main`，随后通过 SSH 上传已验证发布包，因此不会受服务器 GitHub 代理或陈旧 remote ref 影响。

## 安全提醒（上线须知）

- 当前用 HTTP（非加密）。和朋友内部玩够用；若要正式公开，建议后续加域名 + HTTPS（我可以帮你配 Nginx + 免费证书）。
- 密码已加密存储（scrypt），但传输是明文 HTTP——同理，正式公开需上 HTTPS。
- 防火墙只开了 8080 和 22，其它端口默认关闭，是安全的。
