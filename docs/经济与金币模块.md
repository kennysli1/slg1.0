# 经济与金币模块（Economy / Gold）

> 领域模块：`economy`。资源（**5 种**：wood / clay / iron / crop / gold）存量、产率、上限、消耗的唯一 owner。
> 配套：金币的主要产出在 `population`（人口税），消费场景在 `trade`（NPC 订单）与建筑/兵种造价。

本文档聚焦「金币（gold）」这一资源，并顺带说明经济模块的惰性结算与派生管线，供后续维护参考。

## 1. 资源模型

```ts
export const RESOURCE_TYPES = ['wood', 'clay', 'iron', 'crop', 'gold'] as const;
export type ResourceType = (typeof RESOURCE_TYPES)[number];
export type ResMap = Record<ResourceType, number>;
/** 金币无上限：用有限大值代替 Infinity，避免 JSON 序列化变 null 后客户端读到 null。 */
export const GOLD_CAP = Number.MAX_SAFE_INTEGER;
```

- 金币是**第 5 种资源**，与其他 4 种（木/泥/铁/粮）共用同一套存/取/结算接口。
- 金币**无仓储上限**（`capacity.gold = GOLD_CAP`），也**无基础每秒产出**（`baseRate.gold = 0`）。
- 金币的唯一持续来源是**人口税**（见 §5），其余靠一次性 `Grant`（任务奖励、掠夺、贸易交付等）。

## 2. 数据模型

存储集合：`COLLECTION = 'economy'`，键为 `villageId`。

```ts
interface EconomyState {
  villageId: string;
  resources: ResMap;                  // 当前存量（gold 含在内）
  lastTick: number;                   // 上次结算时刻(ms)
  baseRate: ResMap;                   // 各资源基础每秒产率（建筑田等级决定）
  rateModifiers: { source: string; mult: Partial<ResMap> }[]; // 派生管线加成层
  cropUpkeep: Record<string, number>; // crop 每小时消耗（按来源记）
  capacity: ResMap;                   // 仓储上限（gold = GOLD_CAP）
  wasCropDeficit?: boolean;           // 粮食赤字边沿触发标记
}
```

## 3. 惰性结算（settle）

资源不每秒落盘；在**读/写前**按 `(now - lastTick) * rate` 补算：

- `elapsed = (now - lastTick)/1000`。
- 净产率 `netRate`：超额时毛产归 0；crop 还要减 `ΣcropUpkeep/3600`。
- 未超额时自然产出顶到 `capacity` 为止；**超额只暂停该资源生产，crop 口粮消耗仍生效**。
- `lastTick = now`。

**超额（over-capacity）规则**（分城/运输/掠夺通用）：
- 允许 `resources > capacity`（由 `Grant` 等强制入库产生）。
- 超额时该资源**生产暂停**；自然产出不得把存量推过 capacity（只有强制入库可超额）。
- 金币容量 = `GOLD_CAP` 永不触发（等于无上限）。

客户端村庄资源账本在停产时仍读取 `GetResources.rawRate` 显示解除容量限制后的当前理论产量，并同时保留“停产”标记；库存外插与真实结算仍使用 `netRate`，不会因为展示理论产量而继续增长。

### 3.1 金币自愈迁移（重要）
旧存档（新增 gold 前）缺 `gold` 字段，或历史残留 `null`/`NaN`（早期金币税算出 `NaN` 被 JSON 序列化成 `null`）→ `settle` 统一重置为合法数值：
- `resources[t]` 为 `undefined/null/NaN` → gold 重置为 `startGoldAmount`，其余为 0。
- `capacity[t]` 异常 → gold 重置为 `GOLD_CAP`，其余为 0。
- `baseRate[t]` 缺键（旧村庄） → 兜底 0，否则 `grossRate` 算出 `NaN` 污染存量。
- `grant`/`grossRate` 等额外加有限性保护，避免污染后再次持久化为 `null`。

> 监控告警：若线上金币卡住不涨，先查 `data/game.json` 该村庄 `gold` 是否为 `null`。

### 3.2 粮食赤字边沿触发
`netRate(crop) < 0 && resources.crop <= 0` 时，仅在 `wasCropDeficit` 从 `false→true` 时 emit 一次 `economy.CropDeficit`（→ 客户端 `CropDeficit`），避免每次 settle 都触发。

## 4. 命令（MANIFEST.publicActions + 内部）

公开动作仅 `GetResources`（`economy.GetResources`，返回存量/容量/净产率/超额量/是否停产）。其余为**内部命令**，由各模块经 `commands.send` 调用：

| 命令 | 调用方 | 作用 |
|------|--------|------|
| `economy.GetResources` | 各模块/前端 | 惰性结算后返回全量资源快照 |
| `economy.TrySpend` | trade / building / military | 校验余额后扣减，不足返回 `insufficient:<res>` |
| `economy.Grant` | population(税) / trade(NPC交付) / combat(战利品) | **强制入库**（允许超额），返回 `applied`/`overflow` |
| `economy.GetLootable` | combat | 可掠夺量（骨架阶段等于全部存量） |
| `economy.TakeLoot` | combat | 实际扣走战利品 |
| `economy.SetUpkeep` | population / military | 上报某来源 crop 每小时消耗 |
| `economy.SetBaseRate` | building | 上报某资源全村总产率（每小时） |
| `economy.SetCapacity` | building | 上报全村仓储总容量 |
| `economy.SetRateModifier` | population | 注入产率修正器（覆盖式，同 source 只存一条） |
| `economy.GetCropContext` | population | 只读「粮食上下文」（算软上限用，无回环） |

## 5. 金币来源：人口税

金币**无基础产出**，靠人口交税：

```ts
// population.ts
const goldGained = s.currentPop * c.goldTaxPerCivilianPerHour * dtHours;
if (goldGained > 0) {
  await commands.send({ name: 'economy.Grant', from: PopulationModule.NAME,
    payload: { villageId, gain: { gold: goldGained } } });
}
// 客户端展示：goldPerHour = Math.round(currentPop * goldTaxPerCivilianPerHour)
```

- 税率常量 `gold_tax_per_civilian_per_hour`（默认 1）：每人每小时 1 金币。
- 与资源惰性结算同节奏（按 Δt 累加），离线也随 `scheduleSettleAll` 周期结算持续增长。
- 金币因此**随人口规模线性增长**——人口越多、税基越大。

## 6. 相关配置常量（game_constants.csv）

| 常量 | 默认 | 含义 |
|------|------|------|
| `start_gold_amount` | 100 | 新村初始金币 |
| `gold_tax_per_civilian_per_hour` | 1 | 每人每小时金币税 |
| `storage_base` | 800 | 木/泥/铁/粮初始仓储容量（gold 始终 = `GOLD_CAP`） |
| `start_resource_amount` | 750 | 木/泥/铁/粮初始存量 |
| `base_production_per_hour` | 10 | 初始每小时各资源基础产出（换算每秒） |

> 注意：`base_production_per_hour` 不含金币（gold baseRate = 0）；金币只来自人口税。

## 7. 与贸易模块的关系

贸易是金币的**主要消费出口**：
- NPC 订单：玩家向 NPC 买资源 → `want.gold`（全额，按 `trade_npc_gold_per_resource` 计价）；玩家卖给 NPC → `give.gold`（折价，乘 `trade_npc_sell_margin`）。
- `acceptNpc` 即时 `economy.TrySpend(want)` + `economy.Grant(give)`，金币当场增减。
- 商队运输的 `cargo` 也包含 `gold`（按单位计入路线运力）。

## 8. 派生管线（无环约定）

经济模块**只存不回调**，各模块算好后经命令上报：
- `building` → `SetBaseRate` / `SetCapacity`
- `population` → `SetRateModifier`（劳动力增幅）+ 金币税 `Grant` + `SetUpkeep`(civilian)
- `military` → `SetUpkeep`(troops)
- `economy` 只在 `economy.GetCropContext` 被动提供快照给 population（只读，无回环）。

## 9. 设计要点与坑

- **金币别用 Infinity 作容量**：JSON 序列化会变成 `null`，客户端读到 `null` 且后续算术污染。统一 `GOLD_CAP = Number.MAX_SAFE_INTEGER`。
- **自愈迁移必做**：任何 `resources`/`capacity`/`baseRate` 的非有限值都兜底为 0 或默认值，否则会「null→NaN→再次持久化 null」死循环（曾导致金币显示 `+X/时` 却不涨）。
- **超额不砍库存**：改容量/修正器前先 `settle`，容量抬高后自动恢复产出，不会丢资源。
- `cropUpkeep` 的 `building` 来源在 v3 人口模型后已移除（建筑只提供人口上限不耗粮），`stripBuildingUpkeep` 统一剔除历史残留。
