# 09 · 地图与行军系统重做（六边形 + 真实路径 + 途中相遇）

> 状态：**已实现（阶段一）**。本文是"移动模型"这条线的唯一设计入口。
> 战斗结算是另一条线，见 `08_战斗系统重做设计.md`。两条线在"到达/相遇→交战"处对接。

---

## 一、总目标（一句话）

把地图从方格改成**六边形网格**，行军从"瞬时到达"改成**沿真实路径逐格推进**，
玩家能在地图上看到自己部队的**行军路径与实时位置**，敌对出征军**在途同格相遇即战**。

---

## 二、坐标系：axial (q,r)

- 全地图统一用六边形**轴坐标** (q,r)（redblobgames pointy-top 标准）。
- 几何唯一来源：`packages/server/src/infra/hex.ts`——`hexDistance` / `linePath`（逐格路径）/ `neighbors` / `hexKey`。
  内部转 cube 做距离与线性插值取整，保证路径每步都是相邻格。
- 存档、CSV、前端全部改 (q,r)：
  - `config/pve_spawns.csv` 列头 `x,y → q,r`（值语义变轴坐标）。
  - `player` / `pve` / `world_tile` 的坐标字段 `x,y → q,r`；地块 key `"x,y" → "q,r"`。
  - `world_meta.size` 语义从"方形半边长"变为"**六边形半径（环数）**"。
- 前端渲染：`packages/client/src/shared/utils/hex.ts` 负责 axial↔像素（pointy-top）、六边形顶点、插值。

> **存档不兼容**：坐标语义变了，升级需刷档（`npm run reset:season`）。

## 三、行军模型：逐格推进（每格一个 Scheduler tick）

`modules/movement.ts` 的 `Movement` 记录新增：
`path`(逐格路径) / `stepIndex` / `pos`(当前格) / `perStepMs` / `nextStepAt` / `status` / `stepToken`。

- **出征**：用 `linePath(from,to)` 算全程逐格路径；全程秒数 = `hexDistance / 最慢兵种速度(格·h⁻¹)`，
  平摊到每格得 `perStepMs`；登记首个 `step` 任务（铁律#3，时间统一走 Scheduler）。
- **step()**：前进一格 → 更新 `pos/nextStepAt` → 相遇检测 → 到终点则到达，否则登记下一格。
- **stepToken（步进令牌）**：每次登记"下一格"任务时记录令牌，回调携带登记时令牌，
  只有匹配才执行。用于作废因**相遇暂停**而遗留的过期定时任务，防止重复推进（并发安全关键）。
- **resume()**：重启后按 `pos/nextStepAt` 为 marching 的部队续跑（作废旧令牌）。
- **list()** 下发 `path/pos/stepIndex/status/perStepMs/nextStepAt`，前端据此画路径折线并在两格间插值动画。

## 四、途中相遇（本期规则）

- **谁交战**：仅**两支敌对出征军**（type=raid/attack）走到**同一格**（pos 相同）即战。
  返程军（return）视为脱战，**免疫相遇**。同一玩家的部队互不交战。
- **相遇后**：双方**原地暂停**（status=paused，作废各自遗留 step 任务）→ 结算 →
  **胜方按对方相对强度损失部分兵后继续原定行军**，**败方全灭消失**。
- **战报**：发 `movement.Intercepted` Event（胜/败双方各一份，带相遇格 `at`、幸存兵力）。

### 与战斗系统（doc 08）的对接

- **到达目标格**：不自己结算，发 `combat.Engage` 交给有状态战斗模块开/并入战场；
  战斗结束 Combat 发 `combat.BattleEnded`，movement 监听后为幸存者安排带战利品返程。
  坐标对 Combat 为**不透明透传**（字段名 `fromXY/toXY/targetXY` 沿用，值是 `{q,r}`）。
- **途中相遇结算**：本期用 movement 内**自包含的一次性强弱结算占位**（`resolveFieldEncounter`），
  不依赖尚未就绪的"野战有状态战斗"。
  **TODO(阶段二)**：改为发"野战 `combat.Engage`"交给逐 tick 战斗；相遇期间双方 paused，
  `BattleEnded` 后由 `onBattleEnded` 恢复行军。届时删除占位结算。

## 五、前端可视化

- `features/map/map.ts` 从 `<div>` 方格网格改为 **SVG 六边形网格**：
  视野内每格一个 `<polygon>`（本城/玩家村/野怪着色），承载图标。
- **行军路径**：自己每支部队画一条 `polyline` 折线（返程用不同色）。
- **实时位置**：每支部队一个 `<g>` 标记（⚔️/🏇/🏠），用 `requestAnimationFrame` 按
  `nextStepAt/perStepMs` 在当前格与下一格间**像素插值**平滑移动；paused 变色。
- 点击目标格 → 目标面板（坐标显示 q,r，距离用 `hexDistance`）→ 出征沿用 SendRaid/SendAttack。

## 八、前端地图实现现状与踩坑（2026-08 迭代）

> 本节补 09 文「前端可视化」（§五）的**实现细节 + 两个真实踩坑 + 通用经验**，供后续改地图的人 / AI 直接参考。
> 实现集中在 `packages/client/src/features/map/map.ts`；服务端在 `packages/server/src/modules/world.ts` 的 `GetArea`。

### 8.1 已实现能力

- **相机模型**：`viewBox` = 容器真实像素；所有六边形画在世界像素坐标系，由内层 `<g class="camera" id="mapCamera">` 的 `transform="translate(panX,panY) scale(zoom)"` 负责平移/缩放。彻底取代早期「放大 SVG 元素 + slice + CSS scale」三重变换（后者会在某缩放下框出两张地图）。
- **环面无缝**：世界是 axial 平行四边形 `0<=q<W, 0<=r<H`（W=H=41，可调），对 (W,H) 取模无缝。周期向量 `Vx=hexToPixel({W,0})`（纯水平）、`Vy=hexToPixel({0,H})`（带剪切）；`reducePanToLattice()` 把视野中心约束在中心副本 ±½ 晶格内，9 份副本必覆盖视野 → 无边缘留白、无重复、跨边界无缝环绕。相关：`wrapCoord` / `hexDistanceWrapped`（server `infra/hex.ts`）。
- **视口剔除渲染**：`buildHexLayer()` 只渲染真正落入视野（含余量）的格子；副本平铺份数随缩放/容器动态计算。平移/缩放/跳转后由 `scheduleCull()→renderVisibleTiles()` 用**已缓存的 `area.tiles`** 即时重绘（零服务端往返）。`tileAt(q,r)` 用 Map 缓存按 `${q},${r}` 查缓存，O(1)。
- **全图数据一次拉取**：`bootstrap.refreshAll` 用 `req('GetArea', { cq, cr, r: max(W,H), full:true })` 一次性拉全图非空地块，存进 `getCache().area.tiles`。之后纯视觉变换不重拉数据。
- **交互**：左键拖拽平移、滚轮以光标为锚缩放、悬停显示坐标/距离/名称浮层、点击格子弹出派兵/掠夺/进攻目标面板（派兵逻辑见 §五 / `renderTargetPanel` + `bindTargetEvents`，出征沿用 `SendRaid/SendAttack/SendTransport`）。方向键 / 跳转坐标 / 回本城 = `centerViewOn`，双击空白 `resetMapView`。
- 常量：`HEX_SIZE=30`、`ZOOM_MIN=0.7`、`ZOOM_MAX=2`、`INITIAL_ZOOM=1.6`。

### 8.3 踩坑记录（都是真问题，照抄可避雷）

**坑 1：网关会剥离未声明在 schema 的 payload 字段 → `full` 被静默丢弃，客户端只有出生点附近地块**

- 现象：平移/跳转到远处后，远处格子永远渲染为空草地，即便服务端 `getArea(full)` 支持全量。
- 根因：`packages/server/src/gateway/validate.ts` 的 `validatePayload` **只保留 MANIFEST.schema 声明的字段，剥离未声明字段**（收缩攻击面）。而 `world.ts` 的 `GetArea` schema 只声明了 `cq/cr/r`，漏了 `full`。于是 `full:true` 在网关被丢掉，服务端回退成「以出生点为中心」的半径查询，客户端 `area.tiles` 只有出生点附近 → 远处 `tileAt` 查不到 → 空地。
- 修法：`world.ts` GetArea `MANIFEST.schema` 补 `full: { type:'boolean', optional:true }`。
- **通用经验①**：在 KOW 服务端给某个 action 加**任何额外 payload 字段**，必须同步在它的 `MANIFEST.publicActions[...].schema` 里声明，否则被网关剥离，客户端传了也收不到。排查「客户端字段服务端收不到」先查 schema 是否漏声明。

**坑 2：在 mousedown~mouseup 同一手势里重建被点的格子 DOM → 随后的 click 被重定向，点击派兵失效**

- 现象：渲染修好后，左键点格子不再弹派兵面板（之前可以）。
- 根因：点击处理是 svg 上的事件委托，`e.target.closest('.hex-cell')` 取格子。但 `mousemove`(拖拽分支) 每帧 `scheduleCull()` 与 `mouseup` 里 `renderVisibleTiles()` 会 `layer.innerHTML = buildHexLayer()` **整体替换 `.hex-cell`**。指针哪怕只抖 1px，被点的格子就被移出文档；浏览器派发 `click` 时因原 target 已脱离，把事件重定向到父级 `<g class="layer-hexes">`，`closest('.hex-cell')` 返回 null → `setSelected` 不执行 → 面板打不开。
- 修法：把「平移 + 视口重绘」收敛到**位移确超 3px 拖拽阈值**之后才执行；`mouseup` 仅当 `mapDragMoved` 为真才重建一次。纯点击全程不重建被点元素 → click target 保持为被点格子。
- **通用经验②**：凡在 `mousedown~mouseup` 同一次手势内**重建被点元素**（innerHTML 替换等），浏览器会把随后的 `click` 重定向到祖先节点，导致 `closest()` 失效。正确做法：把「重建/重绘」与「吞 click」严格绑定到「确为拖拽」，纯点击路径绝不重建目标元素。
