# 前端设计系统（写任何前端代码前必读）

> 视觉基调：**边境战争沙盘** —— 炭黑蓝与石板灰承载信息，骨白保证阅读，
> 氧化青铜只做结构点缀，金色仅用于稀有奖励和关键确认。世界与场景优先，UI 退后。

---

## 一、架构：Preact + signals（三条规矩）

1. **视图是组件，不是字符串**。所有界面是 `.tsx` 函数组件，禁止 `innerHTML` 拼接。
   JSX 自动转义，不再需要 `escapeHtml`（它只留给非 JSX 场景）。
2. **数据靠信号订阅，不靠整页重渲**。组件读 `dataVersion.value` / `tick.value` 即自动重渲：
   - `dataVersion`（`app/store.ts`）：服务端快照换新了（`refreshAll` 后自增）；
   - `tick`：每秒心跳，用于资源外插、倒计时、进度条。
   读快照本身用 `getCache()`（`app/state.ts`），它不是信号，所以**必须同时读一次 `dataVersion.value`** 才会订阅。
3. **动作一律走 `act()`**（`app/refresh.ts`），不要自己调 `req()`：
   ```tsx
   await act(req('UpgradeBuilding', { slotId }), { okToast: '开始升级' });
   ```
   `act` 负责失败 toast + 成功后 `refreshAll`。

### 文件分工

| 路径 | 职责 | 谁能改 |
|------|------|--------|
| `src/styles/tokens.css` | 唯一的配色/间距/字号/层级来源 | 只有设计系统维护者 |
| `src/styles/base.css` `frame.css` `shell.css` | reset、构件层（面板/按钮/进度条/弹层）、外壳 | 同上 |
| `src/styles/<feature>.css` | 各页面私有样式 | 该特性 owner |
| `src/ui/*` | UI 原子（跨页复用） | 只有设计系统维护者 |
| `src/shell/*` | 顶栏 / 资源条 / 页签栏 / App 根 | 同上 |
| `src/app/{store,refresh,state,config}.ts` `src/api.ts` | 状态、数据层、协议 | 谨慎，改动需同步各页 |
| `src/features/<name>/*` | 页面与其弹窗 | 该特性 owner |

**私有样式只能引用 tokens 变量，禁止写死颜色/字号/间距。** 需要新颜色 → 先加 token。

## 二、UI 原子（`src/ui/index.js` 统一出口）

```tsx
import { Panel, SectionHead, Divider, Empty, Btn, Tag, Icon, IconPlate,
         Bar, TimerBar, Countdown, CostRow, ResChip, canAfford,
         Modal, StatGrid, Stat } from '../../ui/index.js';
```

| 原子 | 签名要点 | 用途 |
|------|---------|------|
| `Panel` | `variant: default\|flat\|sunken\|gold\|danger`、`corners`、`pad` | 一切容器。`corners` 画四角鎏金浮雕，只给重点面板用 |
| `SectionHead` | `sub`、`actions` | 段标题（左侧鎏金竖条） |
| `Btn` | `variant: default\|primary\|danger\|ghost`、`size: sm\|md\|lg`、`block` | 按钮。主操作用 `primary` |
| `Icon` | `icon` 基名、`label`、`size: 2xs\|xs\|sm\|md\|lg\|xl\|2xl`、`fallbackIcon` | 美术图。缺图自动退化为文字徽标 |
| `IconPlate` | 同 `Icon` + `plate: stone\|bare\|gold\|round`、`lvl` | 图标坐在凹陷石板上（建筑/兵种/宝物统一用它） |
| `Bar` | `pct`、`kind: gold\|jade\|ember\|crimson\|steel`、`thin\|tall`、`busy` | 比例条 |
| `TimerBar` | `startAt`、`finishAt`、`label` | 建造/训练进度，自动每秒推进 |
| `Countdown` | `until`、`prefix` | 纯文字倒计时 |
| `CostRow` | `cost`、`timeSec`、`popCost` | 消耗预览，不足自动标红 |
| `canAfford(cost)` | — | 与消耗预览同源的买得起判定 |
| `StatGrid` / `Stat` | `icon`、`label`、`value` | 属性格，替代小字两列文本 |
| `Modal` | `title`、`sub`、`icon`、`onClose`、`foot`、`wide` | 弹层外壳（桌面居中 / 手机贴底） |

### 弹层怎么开

不要自己管挂载，用 `store` 的弹层栈：

```tsx
import { openModal } from '../../app/store.js';

openModal((close) => (
  <Modal title="兵营" sub="Lv3" onClose={close} foot={<Btn variant="primary">升级</Btn>}>
    …内容…
  </Modal>
), 'building');   // 第二参是可选去重 key，同 key 只留一个
```

弹层内容组件同样订阅 `dataVersion`，所以数据刷新后弹层会自己更新，**不需要"刷新弹窗"这类手动逻辑**。

### 反馈规范

| 场景 | 用什么 |
|------|--------|
| 操作成功 | `act(..., { okToast: '…' })` |
| 操作失败 | `act` 自动 toast（已翻译中文） |
| 危险操作（拆除/解散/放弃村庄） | `Modal` 二次确认，禁止 `window.confirm` |
| 历史事件 | 自动进报告页流水，不必额外提示 |

## 三、响应式：两套布局，同一套组件

| 断点 | 形态 |
|------|------|
| `> 720px` 桌面 | 顶栏（徽标 + 资源条）+ 顶部横向页签 + 居中 1180px 内容区；弹层居中 |
| `≤ 720px` 手机 | 紧凑顶栏 + 资源条横向滚动 + **贴底页签栏**；村庄页按“领地全景 → 当前决策 → 深层数据”排序；弹层变贴底抽屉 |

手机端硬要求：**点击目标 ≥ 44px**、正文 ≥ 13px、不出现横向滚动（地图除外）、
底部内容留出 `--tabbar-h + --safe-b` 的空间（`.page` 已处理）。

村庄页的资源账本统一展示木、泥、铁、粮、金币和人口。人口格的主值为总人口/硬上限，悬停说明必须列出劳动人口与军队人口；资源停产时用服务端 `rawRate` 显示恢复生产后的理论产量，人口满员时用 `potentialGrowthPerHour` 显示潜在增长，但库存与人口数字仍只按实际 `netRate` / `popCeiling` 外插。

可读性硬要求：
- 有效信息文字在承载面上的对比度不低于 4.5:1；禁用态才可使用更低对比色。
- 常规说明不小于 12px，正文与按钮优先 14px 以上；不得靠压缩到 8–10px 解决布局。
- 功能性小图标优先简洁战术徽记/矢量式轮廓，复杂厚涂位图留给建筑、角色、宝物和场景。

## 四、美术资源约定

- 引用方式：`<Icon icon="bld_barracks" .../>` → `/art/bld_barracks.webp`。**只给基名**。
- 正式格式是 **WebP**（同画质比 PNG 小 4~6 倍，全套 123 张约 5MB）。CSS 里写 `url("/art/xxx.webp")`。
  唯一例外：`ui_logo` 另存一份 `.png` 给 PWA manifest 与 apple-touch-icon。
- 配置里的 `icon` 列就是基名，服务端 `GetGameConfig` 下发，前端不硬编码映射。
- 缺图不会破图（自动文字徽标），所以可以先写代码后补图。

可用资源前缀：

| 前缀 | 内容 |
|------|------|
| `res_*` | 木/泥/铁/粮/金币 |
| `field_*` | 四种资源田 |
| `bld_*` | 15 种建筑 |
| `unit_*` | 三部族各 10 兵种 + `unit_merc_*` 10 雇佣兵 |
| `trs_*` | 16 种宝物 |
| `pve_*` | 8 档野怪 |
| `ui_tab_*` | 四个页签图标 |
| `ui_icon_*` | `time` `pop` `atk` `def` `speed` `carry` `upkeep` 属性图标 |
| `ui_frame_corner` `ui_divider` `ui_banner_ribbon` `ui_seal_gold` `ui_seal_crimson` `ui_btn_plate` `ui_slot_empty` `ui_lvl_badge` `ui_logo` | UI 构件 |
| `ui_bg_stone` `ui_bg_leather` `ui_bg_parchment` | 可平铺材质 |
| `map_tile_*` | `empty` `grass2` `grass3` `forest` `hills` `water` `oasis` `village` `ruins` |
| `bg_login` `scene_village_ground` `scene_village_ground_night` | 大场景图 |

出图流水线见 `docs/美术生成规范.md`：图像模型出**洋红幕布图** → `tools/art_pipeline.py` 抠像降采样 → 落 `packages/client/public/art/`。

### 村庄场景的坐标契约

村庄主界面把建筑插画按归一化坐标叠在底图 `scene_village_ground` 的裸土垫台上。
坐标模型独立在 **`features/village/scene-layout.ts`**（椭圆环 + 远近缩放 + 8 个扇形角位），
渲染代码只调 `padPos(zone, index, total)`，不关心几何。

**换底图必须重校 scene-layout.ts 的常量**：先跑 `python tools/scene_pads.py` 量一版初值，
再在浏览器里目视微调，确认建筑落在垫台中央而不是压在草地分隔带上。

## 五、跨特性接口（并行开发的契约，签名不可改）

| 模块 | 导出 | owner |
|------|------|-------|
| `features/village/BuildingModal.tsx` | `openBuilding(slotId: string): void` | village |
| `features/army/TrainPanel.tsx` | `TrainPanel()` | army |
| `features/army/UnitDetail.tsx` | `openUnitDetail(unitKey: string): void` | army |
| `features/army/MercCampModal.tsx` | `openMercCamp(): void` | trade |
| `features/trade/TradeModal.tsx` | `openTradeCenter(): void` | trade |

训练建筑由服务端在 `GetArmy.trainable[]` 中汇总，并通过 `trainingQueues[]` 公开进度；
训练与取消只能分别提交 `{ unit, count }` 和 `{ queueId }`，客户端不得显示、选择或传递训练建筑实例。
村庄页点雇佣兵营地 → `openMercCamp()`；点贸易中心 → `openTradeCenter()`。
