# 科研模块（Research / 科技系统）

> 领域模块：`research`。集合：`research`（villageId → ResearchState）。
> 配套前端：`packages/client/src/features/research/academy.ts`（学院详情抽屉）+ `tech-tree.ts`（科技树页）+ `bootstrap.ts`（科技顶级 tab）。
>
> **本文档为 Phase A-H（2026-08-11，commit `af10245`）上线后的现行状态。**

## 1. 职责与定位

学院建筑定时产出科研点(RP) → 科技树页消耗 RP 研发科技 → 科技生效注入各模块。

核心三点：
1. **RP 生产**：学院每级有判定间隔、基础概率、保底增益、概率上限。多学院加速（间隔÷数量），人口越多概率越高（popFactor×currentPop/hardCap）。**保底机制**：失败累积 failStreak → 下一次概率增益。
2. **科技研发**：消耗 RP 开始研发（CSV 固定耗时），研发中可取消（返还 `floor(成本×剩余进度×0.9)`），完成后应用效果。
3. **效果注入**：双轨——**数值型**配置驱动（改 CSV+GM 即可），**机制型**注册表钩子（加 handler+register 不改核心模块）。

科技树和 RP 状态按 `villageId` 独立保存，村庄页/军队页/科技页通过统一村庄列表切换当前工作区。跨村科技（`scope=player`）完成时自动注入同玩家所有村庄；服务端以玩家全部村庄的完成集合计算状态，已在任意村完成的全局科技在其他村显示 `completed` 且不能重复研发。村庄科技（`scope=village`）只影响当前村。

## 3. 状态模型

```ts
interface ResearchState {
  villageId: string;
  rp: number;                          // 科研点余额
  researching?: {                      // 当前研发中
    code: string;                       // 科技 code
    startedAt: number;                  // 开始时间戳
    durationMs: number;                 // 研发耗时
    taskId: string;                     // Scheduler 任务 id
  } | null;
  completed: string[];                  // 已完成科技 code 列表
  academy: AcademyState;               // 学院生产力
}

interface AcademyState {
  failStreak: number;                  // 连续失败次数（驱动保底概率）
  lastCheckTime: number;               // 上次判定时间（惰性回溯用）
  highestLevel: number;                // 村内最高学院等级
  academyCount: number;                // 学院数量
}
```

### 3.1 学院拆除

学院全部拆除时 RP 与已完成科技保留；进行中的研究暂停，重建学院后按剩余时间继续。初次建造学院时重置 `lastCheckTime` 为当前时间（避免回溯白送 RP）。

## 5. RP 生产公式

```
有效间隔 = checkIntervalSec / academyCount × treasureTechIntervalMult
概率 = min(maxProbability, (baseProbability + failStreak × probabilityGainPerFail) × (1 + popFactor × currentPop/hardCap))
```

- 成功：rp+1，failStreak=0，推 `RpChanged`
- 失败：failStreak++，调度下一次 tick
- 人口加成：查询 `population.GetSnapshot` → `1 + popFactor × ratio`（异常时退化为 1）
- `treasureTechIntervalMult` 默认为 1；持有「正直的心」时由宝物模块经 Command 下发，后台调度与 `research.GetState.intervalSec` 同时按倍率缩短，确保科技页显示真实判定间隔。

## 6. 科技效果注入

科技目录与效果明细分离：`research.csv` 只描述节点、前置、作用域、耗时和 RP 成本；`research_effects.csv` 允许一个科技配置多行效果。服务端返回 `effects[]`，并保留首条效果的旧字段用于兼容。科技同类加成先相加再封顶，不再由后完成的科技覆盖前一项。

### 6.1 数值型（配置驱动）

| effectType | 目标模块 | 注入命令 |
|------------|---------|---------|
| `resource_rate` | economy | `SetRateModifier({ source:'tech:xxx', mult: {[key]: value} })` |
| `combat_atk` / `combat_def` | military | `SetTechEffects({ combat })`，按兵种形态聚合后输出最终战斗快照 |
| `march_speed` | military | `SetTechEffects({ marchSpeed })`；movement 通过 `GetMarchSpeedSnapshot` 取得最慢速度并在出发/续行/返程锁定 |
| `pop_growth` | population | `SetTechGrowthMult({ mult })` |

### 6.2 机制型（注册表钩子）

```ts
// research/mechanisms.ts（未来拆分）
MechanismRegistry['imperial_pop_boost'] = (ctx) => {
  ctx.commands.send({ name: 'population.SetTechGrowthMult', ... });
};
```

加新机制：写 handler → `registerMechanism('code', handler)` → 不改 ResearchModule 核心。

### 6.3 跨村科技

`scope=player` 的科技完成时，通过 `playerByVillage(villageId)` → `playerVillages(playerId)` 遍历所有村 → 逐个 `applyTech`。

## 9. 踩坑记录

### 9.1 `eventPushMap` key 必须匹配 `bus.emit` 的 event name

key = `'research.TechCompleted'` → emit `{ name: 'research.TechCompleted' }`。若 key 无前缀（`'TechCompleted'`），Gateway 订阅不到 → push 不到客户端。

### 9.2 `onAcademyChanged` 读取 `building.GetLayout` 的结构

返回 `{ zones: { inner: { placed }, outer: { placed } } }`，非顶层 `placed` 数组。

### 9.3 `reloadConfig` 必须调用 `research.setConfig(newConfig)`

GM 改科研参数后热重载会遍历所有模块调 `setConfig`。ResearchModule 未实现该方法 → 热重载不生效。已补充。

### 9.4 初次建造学院时 `lastCheckTime` 未重置

`lastCheckTime` 在村庄创建时已初始化。建学院后惰性回溯会结算建院前的大量空 tick → 白送 RP。修复：academyCount 0→>0 时 `lastCheckTime = now()`。
